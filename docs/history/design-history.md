## 5. 三条技术路线的比较与选择

| 路线 | 主要收益 | 主要成本与不确定性 | 当前定位 |
| --- | --- | --- | --- |
| 纯 Avalonia | C# 与课程架构衔接直接；一套桌面界面体系；覆盖 Windows、macOS、Linux | Markdown 选区、原文映射、高亮和阅读恢复需验证；不能只凭可渲染 Markdown 判断可行 | 当前评估基线 |
| Avalonia + Web 内容区 | 可保留 C# 架构，并利用 Web 处理富文本和图形交互 | 两套界面体系及桥接；主题、焦点、滚动和状态同步；WebView 平台差异；课程接受度需确认 | 备选，未采用 |
| 全 Web 桌面应用，如 Electron + Vue + TypeScript | 富文本、选区和图形交互处于统一 Web 界面；可明确实现课程架构 | 桌面进程通信、资源占用、技术迁移；Vue 不自动等于完整 MVVM；“不要做 Web”的解释存在关键不确定性 | 未获课程适用性确认，暂不作为默认路线 |

讨论中曾基于交互适配性优先推荐全 Web 路线；在补充老师的口头限制后，当前选择改为先评估纯 Avalonia。打包成桌面程序不能自动绕过老师的技术限制。若未来重新考虑 Web 路线，需要澄清老师限制的是浏览器网站还是 Web 主界面技术。

三条路线都可能做出统一、精致的 UI。纯 Avalonia 不等于界面粗糙，混合方案也不必出现可见的拼接边界；实际成本需要验证，不能从技术名称推定效果。

### 5.1 跨平台范围

macOS 为主要开发和使用环境，Windows 为首版次要支持及课程演示环境。用户已提供 Windows 11 x64、华硕 ROG 幻16 Air 作为实际验证设备；此信息不代表 Windows 已通过验证。Linux 可作为后续目标，不扩大当前验证范围。不同系统及 CPU 架构需要相应发布产物，并分别验证输入法、快捷键、缩放、窗口及文本交互。

纯 Avalonia 和 Electron 均支持三大桌面平台，但支持的系统版本取决于所选版本。混合方案还取决于具体 WebView 后端及运行依赖，不能从外壳跨平台推导出内部行为完全一致。

### 5.2 当前选型状态

已选：纯 Avalonia、四工程、本地 SQLite、单套 OpenAI 兼容接入、LiveMarkdown 加来源适配层。具体职责及扩展边界见第 10–17 节。

待定：正式版最终依赖版本、网络布局算法与控件细节、数据库迁移与平台凭据封装的具体实现。Worklog 未完成复用盘点，不承诺复用比例。原型依赖版本是验证依据，不自动成为正式版依赖锁定。

## 6. 对参考项目的结论

[Starward](https://github.com/meilingrl/Starward) 是 C#／WinUI 桌面应用，不是全 Web 界面路线。它可以作为产品与界面参考，但不能直接作为课程架构合规模板。

当次检查发现，主视图后台代码承担状态、页面导航及更新检查；服务注册主要使用具体业务类，页面通过服务定位获取服务；主导航使用 Frame.Navigate。这些与课程强调的薄 View、ViewModel 职责、接口注入以及三层服务化导航有差距。工程成熟度与课程指定结构是否符合是不同评价维度。

这是对已检查代码路径的静态判断，没有运行项目，也没有完成其课程工作量和交付要求的全面验收。

## 7. 历史记录：2026-10-22 的低成本验证提议

已提出的方向是独立、可丢弃的小原型，先用固定回答验证：

**渲染 Markdown → 选中文字 → 创建模拟分支 → 返回并高亮原文。**

重点在于带格式文本的选择与来源定位，不以普通文本或截图代替验证。若这条链路可行，再讨论模拟流式追加、调整窗口后的定位、重启恢复以及 Windows／macOS 双平台检查。

暂不接真实 AI、不做完整网络图、不引入正式项目架构。之前提出“先用约半天预算评估”的想法仅为限时探查建议，不是工期承诺或已经批准的执行计划。

下一轮仍需确定：原型位置、候选控件、最小测试样本、通过和停止条件、双平台验证条件。技术验证通过也不等于产品价值已得到证明；后者仍按需求文档的使用场景和延迟回顾方法评估。

**当时停止点：文档整理完成后继续讨论验证方案，不启动原型或开发。** 后续有限原型授权及验收见第 9 节。

## 9. 原型验收与当时停止点 · 2026-10-23

用户已明确确认本轮验证通过。验证对象是 [纯 Avalonia 原型 v0.2.1](../../prototypes/avalonia-chat/README.md)，不是正式产品。

| 验证项 | 结果与证据边界 |
| --- | --- |
| 视觉与分支交互 | 用户确认视觉效果、拖选文字、创建分支及返回来源可用 |
| 模拟流式与退出 | 切换会话后持续输出；退出提示，确认后停止并保存部分回答；不后台常驻 |
| 窗口调整与定位 | 修复窄窗正文裁切，实机 1240→约 1007→1240 宽度下正常换行，返回来源高亮可见；自动回归另覆盖长段落字符锚点 |
| 真实重启 | 退出进程后重新启动，恢复当前会话、草稿、来源与阅读状态、已停止的部分回答；不自动续写 |
| 自动验证 | 本轮实现记录与独立复查均为 Release 31/31；包含保存失败、损坏文件保护和退出保存期间禁止新编辑；本次文档收尾未重复运行测试 |

用户观察到的回答分段出现，是固定示例约 16 秒的分块模拟节奏，已明确确认，不作为界面卡顿缺陷。本轮没有完成性能基准测试。

可延续的设计依据：来源锚点与阅读位置分离；生成任务独立于当前视图；增量更新正文；停止保留部分内容；保存失败不关闭丢弃状态。原型控件适配与回归场景可供正式实现参考。

当时仍待正式选型：Markdown 支持范围及解析／渲染方案、存储与迁移、真实 AI 与上下文组装、总结更新策略、网络布局、课程导航及工程边界。原型的单块选区和 Markdown 子集不是完整需求验收，也不自动成为正式版能力上限；JSON 保存不等于正式选择 JSON。Windows 实机、真实 AI、总结网络和使用价值验证尚未完成。

**当时停止点：保留原型作为参考，继续讨论正式版架构与技术方案；不启动正式开发，不默认沿原型工程直接扩建。**

## 18. 已合并：复审后的 D1–D8 决策

本次用户授权将已有讨论落实到现行文档。依据是[复审后讨论记录](../reviews/review-20261023-023314-sgt/discussion-decisions.md)，不是冻结 v6 中尚标注待决的推荐。五轮报告与 v1–v6 不修改；审查建议未被逐条确认的部分不冒称用户批准。正式开发仍未启动。

| 决策 | 当前规则 |
| --- | --- |
| D1 总结时机 | 当前会话的排队／生成回答完成或停止后才接受总结，接受时冻结终态正文与背景；部分回答保留不完整标记 |
| D2 版本操作 | 每会话最多一个未结束总结任务、一个待采用版本；候选未处理前不生成下一版。只有当前采用版本直接可编辑；候选／历史只读，先采用再编辑。基线变化时说明替换并确认 |
| D3 排队配置 | 接受操作时冻结目的地、模型参数和输入范围；修改配置不改变旧队列，取消后显式重发，不静默转送其他服务 |
| D4 单实例 | 同一数据库只有一个写入／调度实例；重复启动优先回到已有窗口，异常退出后可安全重开，不删库解锁 |
| D5 导航历史 | 主 ViewModel 管理各工作区／主区本次运行的历史；切换后可恢复，ContentStack 是唯一活动业务内容栈，服务／View 不自建业务栈 |
| D6 重启与退出 | 重启恢复最后有效页面、位置及草稿，不恢复完整后退历史。退出保存失败可重试或返回工作区；已取消任务和队列不复活，重试保存最新状态 |
| D7 Markdown | 首版目标为段落、标题、列表、引用、代码、粗体／链接／行内代码与跨段选择；复杂结构不作为可分支门槛，引用无法验证时拒绝，原文仍可读；目标不等于已验证 |
| D8 布局分期 | 首版自动布局与浏览，完整计划保留拖动；按可承接拖动的职责边界设计，不提前实现复杂编辑器 |

实现设计还应吸收复审指出的不变量：迟到分块不得改变终态；旧检查点不得回退新内容；自动标题不得覆盖手动命名；来源依赖必须可持久恢复。它们是待实现和验证的约束，不是已有测试结果。

## 26. 网络交互样例验证收尾 · 2026-10-23

用户确认基础交互、局部拖动反馈及悬停吸引效果可行，明确本轮验证结束，效果细节以后微调。资产与各轮证据见[网络交互样例](../../prototypes/network-layout/README.md)。

- 样例：原生 Avalonia 12.1.4，两组固定数据；圆点短标题、来源路径高亮、搜索、平移缩放、打开总结返回和新增保留旧位置。径向放置加粗略碰撞检查已用于观察效果，不等于最终布局算法。
- 拖动反馈：被拖节点留在新位置，直接邻居轻微跟随并回稳；有位移上限，不全图传播。0–100%强度，默认30%。
- 悬停反馈：无需点击，靠近圆点产生轻微吸引，离开回位；独立开关，共用强度，最大5个界面逻辑像素。仅影响显示，不修改布局坐标，点击兼顾原位置。停稳后停止刷新。
- 证据：Release构建0警告／0错误；无窗口数值检查覆盖响应、强度、上限、范围、关闭和回稳停歇；工具检查真实窗口的节点拖动、选择、开关及滑动条。连续交互观感由用户试用确认。
- 边界：不证明Windows、大规模性能、真实数据库集成、布局持久化或知识回顾价值；未实现全图力导向、碰撞排斥、文字精确避让。原型自绘及单文件窗口不是正式MVVM方案。

稳定布局与短暂装饰位移可以并存：“不持续运动”指平时稳定、无输入且回稳后停止计算，并非禁止交互反馈。此次验证不自动改变D8首版自动布局与基础浏览的分期；手动拖动、位置保存与装饰反馈的正式交付范围需与架构讨论分别确认。样例停止扩展并保留，下一步讨论正式接入，不直接复制样例为产品实现。
