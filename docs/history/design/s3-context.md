# S3 上下文预算与压缩

验收依据：交接 §2.5、§5 S3（“真实长会话检查纠正、来源和指代；压缩失败不静默截断”）；需求 §6.2 末段、§9.6；架构 §4.1（ContextSummary）、§4.2、§6、§6.1–6.3。参数由实现者决定（交接 §4），见文末与[决策记录](../../design/decisions.md)。

## 预算

`预算 = 上下文容量 − 输出预留 − 安全余量`

| 项 | 取值 |
| --- | --- |
| 上下文容量 | 模型能力 `ContextWindowTokens`（E4）；未填写时 32,000。设置页可填写，并说明压缩会增加调用与等待 |
| 输出预留 | 模型配置的 `max_output_tokens`；未设置时 4,096 |
| 安全余量 | 容量的 10%，至少 1,000 |

**估算器**（`TokenEstimator`，Core）：按 Unicode 字符计——中日韩及其他非 ASCII 字符各 1 token，ASCII 每 3 个字符 1 token（向上取整）；每条消息另加 4，每个请求另加 16（按真实服务的计费 token 校准，见 D-011）。故意偏高：低估会让服务端拒绝请求，高估只会稍早压缩。服务在流式结束时返回 `usage` 时，记入 `ai_request`（迁移 v5），用于核对估算；不向服务请求额外选项，以免不兼容。

**按模型校准（2026-11-05，迁移 v9）**：固定估算对 Claude（经 Pinaic 中转）偏低——长请求约 1.17 倍，另有每请求约 690 token 的固定附加（两个字的问题计费 650，是中转加的隐藏提示），超过 10% 余量。处理：

- 每个请求记下自己发出时的估算（`ai_request.estimated_tokens`），与服务返回的 `prompt_tokens` 并存；
- 规划前按“地址＋模型”取最近 50 对，拟合 `计费 ≈ 倍率 × 估算 ＋ 附加`（`TokenCalibration`）：倍率取最小二乘斜率，限制在 1–3，只在样本大小跨度够大时（最大 ≥ 1,000 且 ≥ 最小的 4 倍）才拟合，否则为 1；3 个样本起先剔除远离其余的报告（残差超过中位数 ＋ max(4×MAD, 100 ＋ 25% 中位数)）再拟合；附加取剩余样本的最大残差，保证覆盖它们；
- 只会让估算变大，不会因某个模型计费偏少就放宽；附加在预算里最多取可用空间的四分之一，任何报告都不能让模型没有空间（被拒的发送不产生请求，否则永远恢复不了）；
- 规划器仍比较估算值，`ContextBudget.Available` 是可用空间折算成的估算单位；`Fits`、`Predict` 与上下文提示行用计费 token；
- 读取失败时用未校准的估算，不阻塞请求；服务不返回 `usage` 时同样不校准。Kimi 把 `usage` 放在最后一个 `choice` 里，现在也读取。

压缩自己的摘要请求不受此预算约束：它携带约 4,000 估算 token 的固定块并预留 16,384 输出，相当于假定窗口至少约 24k。窗口更小的模型（例如部分本地模型）在压缩时可能超限，见 TRACK“发现”。

## 选择顺序

组装结果（S2 的 `BranchContext`）按时间排列。**必需项**原样保留、永不压缩：

1. 当前问题；
2. 本分支的第一个提问（带引用选文）；
3. 直接父会话的来源回答及其提问（必要来源上下文）。

其余按会话切成**块**：从该会话范围的第一条消息起依次累加，达到 4,000 估算 token 且位于提问边界时封闭一块；范围末尾不足一块的部分为**尾块**。块边界只由会话开头决定，会话增长不改变已封闭的块，因此摘要可以复用。祖先的范围已冻结，它的块对所有后代相同。

全部原文在预算内就不压缩。否则按时间从最早开始，逐块改用摘要，每换一块就重新检查是否放得下：先压缩已封闭的块（可复用），仍放不下再压缩尾块（只用于本次），最后仍放不下就拒绝（见“失败与超限”）。因此最近的问答总是最后才被压缩，且不会按固定轮数截掉。估算时未生成的摘要按 800 token 计，已有摘要按实际长度计。

## 上下文摘要

- 表 `context_summary`（迁移 v5）：所属会话（被覆盖消息所在的会话，MW-C02）、覆盖的 `seq` 范围、覆盖消息 ID 序列的哈希、提示词版本、生成所用模型、正文、创建时间。随所属会话删除（`CASCADE`，纯从属行）。
- **复用：**会话、范围、哈希、提示词版本都相同才复用。哈希覆盖“选中的消息 ID”，所以范围内某次回答后来被重试取代时，哈希改变，旧摘要不再被选用（相当于失效），不需要另存失效标记。
- **只从原文生成**，不对摘要再摘要。摘要要求保留：背景与已确认的事实、用户提出的要求与纠正（以纠正后的为准）、未解决的问题、指代（“它”“那台车”指什么）。
- 发送时每段摘要以一条 system 消息出现在它覆盖的位置：“以下是较早对话（第 x–y 条）的摘要，原文保存在本地：…”。
- 不进入网络、没有候选或已读状态，界面上不单独列出。

## 调度

摘要是回答任务的前置步骤，在**回答任务自己的执行槽**里依次完成，再发出回答请求：不另占槽、不排队等待自己，全局两路的限制不变；停止回答同时停止摘要请求。摘要请求使用回答任务冻结的模型快照与密钥，不暗换服务，并记入同一任务的 `ai_request`（一个任务可有多次请求，E3 已预留）。任务记录实际输入：原样发送的消息 ID（`input_message_ids`）与所用摘要 ID（`input_summary_ids`，迁移 v5，MW-C16）。

## 失败与超限

| 情况 | 结果 |
| --- | --- |
| 当前问题与必需项本身超出预算 | 不接受提问，输入保留；提示缩小选区或在设置中调整模型与上下文容量 |
| 全部压缩后仍超出预算 | 同上，提示历史过长，可从中分支后继续 |
| 摘要请求失败或被停止 | 回答标为失败（`CompressionFailed`）或已停止，提问保留，可重试；已生成的摘要保留供重试复用。只在原文放不下时才压缩，所以没有“改用原文”的退路 |
| 摘要在输出上限处被截断或为空 | 绝不使用截断的摘要；在同一任务内再请求一次，仍不完整则按上一行失败（D-015） |
| 生成后的摘要比估计长、实际总量超出容量减输出预留 | 同摘要失败 |

压缩成功时，该回答下方轻量提示“较早的对话已压缩为摘要发送，原记录完整保留”，不弹窗。

## 迁移 v5

- `context_summary` 表；
- `generation_task.input_summary_ids`（JSON 数组，默认 `[]`）；
- `ai_request.prompt_tokens`、`ai_request.completion_tokens`（服务返回时才有）。

## 迁移 v9

- `ai_request.estimated_tokens`（发出时的估算；之前的请求为空，不参与校准）；
- 索引 `generation_task_by_model (model, base_url)`，供规划前读取最近样本。

## 参数（交接 §4，可调）

| 参数 | 值 |
| --- | --- |
| 默认上下文容量 | 32,000 |
| 未设置时的输出预留 | 4,096 |
| 安全余量 | 10%，至少 1,000 |
| 块大小 | 4,000 估算 token |
| 未生成摘要的估算长度 | 800 |
| 摘要请求输出上限 | 16,384（4,096 时推理模型在试用中把上限全用于推理，见 D-015） |
| 摘要请求次数 | 截断或为空时在同一任务内再请求 1 次，共 2 次 |
| 提示词版本 | 1 |
