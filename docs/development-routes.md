# 两条开发路线

2026-10-25：Claude 与 Codex 三轮讨论、相互检查后形成；用户已认可按此整理并作为后续执行依据。本次完成结构整理，不启动产品开发。

共同依据：[需求](requirements.md)、[架构](architecture.md)。具体模块与 S0–S6 依赖参照[详细设计交接](reviews/claude-design-readiness-20261024-172436/detailed-design-handoff.md)；现行文档优先于历史审查副本。

## 各自怎样推进

- **Claude 自主路线**：在已授权范围内，自主推进端到端实现与验证，尽早触及后续阶段、发现隐藏问题。允许可逆实现试验，少做早期视觉打磨；仍遵守共同产品与架构约束。
- **用户与 Codex 协作路线**：用户参与有用目标、关键取舍和试用反馈；Codex 在已授权任务内连续完成必要设计、实现、验证与修复，产出可理解、可使用、可用于课程提交的产品。
- 人机协作不意味着每个操作或阶段都需人工确认。只有产品取舍、超出授权或明确要求审批的操作需要另行决定。不设置 Claude 领先幅度，也不保证哪条路线更快；开发范式比较只是附带经验。

## 共同顺序与检查重点

先简要梳理稳定身份、来源依赖、祖先冻结范围、版本归属及事务／删除边界；不提前冻结全部字段与索引。随后以薄的端到端功能推进：存储、生命周期和课程桌面骨架 → 聊天与分支／返回来源 → 上下文、总结和网络。故障恢复、迟到事件、并发与保存失败随对应功能验证，不集中拖到最后。

来源锚点遵守现行架构 §5 的源块范围、块内显示位置与完整性校验，以及消息级降级行为，不重新当作未决设计。Windows 11 的选区、来源恢复和阅读位置应尽早实机验证。课程导航与职责分离从骨架阶段检查，不用凑类数量代替合规判断。

模拟流、无界面测试、真实服务与实机交互各自说明实际覆盖。真实杀进程配合模拟流可以验证本地检查点恢复及不重发，但不能证明供应商行为；CI 不替代 Windows 11 实机。外部条件缺失时及时说明影响，继续独立可做的工作。

## 交流与隔离

各自 `TRACK.md` 保留当前阶段、下一步和少量重要发现；发现写清现象、依据／复现方式与影响即可。重要风险及时反馈，不等阶段结束。阶段反馈说明如何体验、实际验证了什么、还有什么未验证，不新增认证体系。

双方可按任务需要只读查看相关发现、证据和代码，采纳结论前独立验证；复制代码或合并仍遵守 [分支规则](../AGENTS.md)。共同需求更正先进入 `main`，再同步到开发分支。

两个 worktree 只隔离文件，正式程序还需分别使用数据目录、单实例标识及凭据命名空间。这是实施要求，尚未验证完成。早期试用优先使用专门准备的测试数据，用户提供的数据不视为可丢弃；有价值数据须由测试过的迁移和备份保护。

## 当前边界

本次互审是方案判断，不是实现验收。产品价值需要真实试用；推送、外部服务与付费调用遵循用户已有授权，不由路线文档自动扩大授权。
