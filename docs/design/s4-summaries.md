# S4 总结与版本

验收依据：交接 §2.6、§5 S4（“需求 §11 总结相关行及补充场景”）；需求 §6.4、§6.5、§7.1–7.2、§8.1、§11；架构 §4.1（SummaryNode、SummaryVersion、SummaryReadState、SummaryEditDraft）、§4.2、§8、§8.2、§10。网络（S5）、导出与会话删除（S6）不在本阶段；S5 之前，“总结网络”分区先以列表列出本工作区的总结。

## 数据（迁移 v6）

| 表 | 内容 |
| --- | --- |
| `summary_node` | 稳定 ID、工作区、来源会话（唯一）、当前版本、候选版本、基础标题、显示名、命名来源（`base`／`auto`／`manual`）、创建与更新时间 |
| `summary_version` | 稳定 ID、所属节点、节点内序号（创建顺序）、标题、Markdown 正文、覆盖范围上界（来源会话的 `seq`）、来源（`generated`／`edited`）、基线版本、任务、模型、创建时间 |
| `summary_read_state` | 按版本：是否已读、已读来源（`progress`／`manual`／`edit`）、最大阅读进度、阅读位置；随版本删除 |
| `summary_edit_draft` | 按节点至多一份：基线版本、草稿标题与正文、更新时间；随节点删除 |

- 节点与版本互相引用，外键设为延迟检查，在同一事务内建立。节点的当前版本只能为空（仅在建节点的事务内）或本节点的版本，由事务内检查保证。
- `generation_task.kind` 增加 `summary`（总结）与 `naming`（同名二次命名）；总结任务另记覆盖范围上界与发起时的当前版本（采用基线）。表结构的 CHECK 只能重建表来修改，迁移按 SQLite 的重建步骤在一个事务里完成并做外键检查。
- 覆盖范围：来源会话从第一条到 `seq ≤ 上界` 的消息，每个提问取最新一次尝试。上界在接受“总结”操作时冻结，是会话最后一条已结束消息。

## 生成

1. “总结此会话”只在以下条件都满足时接受：本会话没有未结束的回答；没有未结束的总结任务；节点没有候选版本。否则说明原因（“先完成或停止回答”“正在生成总结”“先采用或丢弃候选”）。
2. 输入：覆盖范围内的消息；分支另附“必要背景”——来源引用及父会话的来源回答，标明“仅作背景，不要总结”。超出预算时复用 S3 的规划与摘要（摘要在总结任务自己的执行槽里生成）。
3. 输出：第一行“标题：…”，其余为 Markdown 正文。要求保留问题背景、主要解释、未解决问题与原回答中的不确定性，不补充对话中没有的内容。输出上限 16,384（同 D-015 的理由）；只接受服务正常结束、标题和正文都非空的结果，否则任务失败、不写任何版本（MW-C06）。总结任务排在用户优先级，可停止。
4. 成功：没有节点时，在一个事务里建节点与版本 1（当前，未读），基础标题和显示名取生成的标题；已有节点时，版本作为候选写入。正文在成功前只在内存里，失败、停止、退出或重启后中断都不留下版本。
5. 失败与中断在会话页可见，并可再次“总结”；不自动重试。

## 版本操作（每一项一个事务）

| 操作 | 前提 | 结果 |
| --- | --- | --- |
| 采用候选 | 没有未保存的编辑草稿 | 候选成为当前；候选的已读记录保留（采用已读的候选不重置未读）。如果候选生成时的当前版本已不是现在的当前版本（期间手改保存或设为当前），先说明“将替换当前版本，当前版本保留在历史中”并确认 |
| 丢弃候选 | — | 删除候选的正文与阅读记录 |
| 编辑 | 只针对当前版本 | 草稿独立自动保存（停止输入 1 秒后），显式“保存”才产生版本；与基线完全相同则不增版本并删除草稿。新版本来源 `edited`、沿用基线的覆盖范围、成为当前、记为已读（`edit`） |
| 设为当前 | 目标是已保存版本（非候选）；没有草稿 | 只切换指针，不删除其他版本，不改已读 |
| 删除版本（可多选） | 不含候选；没有草稿；没有未结束的总结任务 | 删除正文与阅读记录。删到当前版本时，若还有保留版本，切换到“上一保留版本”：按创建顺序，被删当前版本之前最近的保留版本，没有则取最近的保留版本（MW-C17），确认框里写出将切换到哪一版。删光全部已保存版本时删除节点；此时若有候选，先要求采用或丢弃。删除前说明不可恢复 |

迟到的结果：删除节点要求没有未结束的总结任务，所以不会有迟到的总结重建已删除节点；迟到的命名结果在提交前检查节点仍存在。

## 阅读状态（U2、MW-C30）

- 阅读进度＝正文已进入视口的最大比例（视口底部位置／正文高度）。**阈值 90%**，且该版本在本次打开中**累计可见至少 8 秒**才记为已读——整篇一屏可见的短正文也要停留，不会“打开即已读”。参数可调。
- 总结页有“标记为已读／标记为未读”开关；改回未读清除已读来源，保留最大进度。
- 只打开、在列表中选中或查看元信息不记已读。查看旧版本只影响该版本。手改保存的版本记为已读。
- 阅读位置按版本保存，恢复方式同会话（S2 的定位器与阅读线）。

## 节点标记（MW-C07）

由版本状态推导，分别显示，不只用颜色：**未读**＝当前版本没有已读记录；**有候选更新**＝存在候选；**有后续内容**＝来源会话在当前版本覆盖上界之后还有已结束的消息。当前版本改变时按新当前版本自己的记录显示。

## 命名（§10）

- 规范化：Unicode NFKC、去首尾空白与首尾标点、连续空白合一、按不区分大小写比较。
- 节点首次生成后，若同一工作区里规范化后同名的节点有两个及以上，排一个后台命名任务：给出整组每个节点的当前标题、正文开头与现有显示名，要求为每个节点给出有依据的区分词，现有区分词仍准确时保留；不能区分的可以返回空，允许同名。
- 提交前检查：组成员与各自当前版本未变、节点仍存在；手动命名的节点不改。结果写为“基础名－区分词”，不新增版本、不改已读。失败保留原名，不自动重试。
- 手动改名后命名来源为 `manual`，自动命名不再覆盖。采用候选或设为当前后，若新当前版本的标题规范化后与基础标题不同且名称不是手动的，基础标题与显示名改为新标题，再检查同名组。

## 界面

- 会话页标题栏：“总结此会话”或“重新总结”；已有总结时显示“总结：〈显示名〉”入口与标记；生成中显示进度和“停止”；失败显示原因与“重试”。
- 总结页（内容路由 `SummaryRoute(节点, 版本?)`）：显示名与版本信息（第几版、生成／手改、覆盖到第几条、生成时间）、标记、正文（同一 Markdown 渲染）、阅读开关、“回到来源会话继续”、候选区（并列说明“新生成（候选）”与“当前”，采用／丢弃）、编辑、历史（列表、查看、设为当前、多选删除）。
- “总结网络”分区：S5 之前为本工作区的总结列表，显示名、标记与来源会话。
