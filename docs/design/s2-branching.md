# S2 分支与返回（连同 E1）

验收依据：需求 §11 前四行——从选句创建分支并继续追问；逐层返回来源；再次进入与普通切换各自恢复位置；关闭重开后消息、来源、阅读位置和草稿可恢复。需求 §6.2、§6.3，架构 §3.3、§3.4、§4.1、§4.2、§5、§6。演进接缝 E1 随本阶段落地；E2–E4、E6 已在迁移 v3 落地，名称见 [演进接缝](evolution-seams.md)。

## 数据（迁移 v4）

| 表 | 内容 | 引用 |
| --- | --- | --- |
| `branch_source` | 主键为子会话；父会话、来源消息、来源块序号；引用文字；锚点 JSON、锚点格式版本、渲染配置身份；创建时间 | 三个引用均 `RESTRICT`（跨实体） |
| `branch_context_range` | 主键 `(子会话, 祖先会话)`；`depth`（根为 0，按此排序，无需递归）；`max_seq` 为该祖先允许使用的最大消息序号 | 子会话 `CASCADE`（纯从属行），祖先 `RESTRICT` |
| `reading_position` | 主键 `(会话, 槽位键)`；视口顶部的消息、块序号、适配层细节 JSON 与格式版本；更新时间 | 会话与消息 `CASCADE`（纯从属行） |
| `draft` | 主键 `(会话, 槽位键)`；输入框文字；更新时间 | 会话 `CASCADE` |

分支父关系只存在 `branch_source`，`conversation` 表不加父列（架构 §4.1“不重复维护第二份事实”）。父会话里的分支入口由 `branch_source` 按来源消息推导。

## 创建分支（一个写事务）

在事务内检查，任一不满足即拒绝且不留任何行：

- 来源消息属于指定父会话，是回答，状态已终态（完成、停止、失败、中断；取消的回答没有正文），正文非空。被后来重试取代的旧尝试同样可以分支（需求 §6.2“旧尝试的正文及从它创建的分支入口保留可读”）。
- 引用文字非空、不超过 4,000 字；锚点 JSON 不超过 64 KB。
- 子会话与父会话同工作区（子会话直接取父会话的工作区，不接受外部传入）。

插入：子会话（无标题）、来源记录、祖先范围——复制父会话的全部范围行（depth 不变），再加 `(父会话, depth = 父链长度, max_seq = 来源消息 seq)`。父会话无范围行时即为根。来源是本会话自身、环或悬空引用都不可能出现：子会话是新 ID，范围只复制已存在的祖先。

## 上下文组装

`BranchContext.Assemble`（Core，纯函数）：

1. 按 depth 从根到父，对每个祖先取 `seq ≤ max_seq` 的消息，按 S1 规则“每个提问取最新可用尝试”选择。**例外：**每段范围的最后一条（`seq = max_seq`，即下一层分支的来源回答）即使是失败或中断的部分正文也保留——分支就是针对它的。
2. 然后是本会话自己的消息，同样按 S1 规则。
3. 链上每个分支会话（含当前会话）的第一个提问，在发送材料中前置“关于上文中的这段内容：> 引用”。存储中的提问不变。

来源回答之后被重试替换不影响已有分支：范围按 seq 冻结，新尝试的 seq 更大，不在范围内。任务的 `input_message_ids` 记录实际使用的全部消息 ID（含祖先）。预算与压缩在 S3。

## 锚点与渲染（Desktop 适配层）

- 回答用 LiveMarkdown.Avalonia 2.5.1 渲染，配置身份 `livemarkdown-2.5.1/default-pipeline`。提问仍为纯文本。
- 锚点沿用组件小样已验证的格式 1：每段记录源文区块范围、同范围序号、显示文字哈希、块内显示位置与引用；外加正文前缀长度与哈希；仅当源块与显示文字完全相同时记录精确原文起点。恢复先全部校验再改变选区，任一不符即拒绝。锚点相对于来源消息的某个文本块（E2 的块序号，首版恒为 0）。
- **降级（MW-C13）：**锚点无法恢复时，仍凭消息 ID 滚动到来源消息，显示保存的引用文字并提示“无法精确定位原句”；不在消息内搜索相同文字。
- 只有已终态、正文已保存的回答能发起分支；生成中的回答不显示“创建分支”。

## E1 视图槽位

- 工作区运行期状态分两层：`WorkspaceRuntime`（工作区）→ `ViewerSlot`（槽位）。当前主区、各主区内容栈属于槽位。首版每个工作区只有一个槽位，键为 `primary`。
- 阅读位置与草稿以 `(会话, 槽位键)` 为主键；页面创建时得到所在槽位的键。
- 导航请求可携带目标槽位，缺省为发起请求的槽位；首版只有 `primary`。“返回来源”在当前槽位中打开。

## 返回、再次进入与普通切换

| 操作 | 导航意图 | 结果 |
| --- | --- | --- |
| 子会话页“返回来源” | `ReturnToSource` | 在当前槽位的探索栈压入父会话页，定位并高亮来源；失败按降级处理。后退回到子会话 |
| 父会话里点分支入口 | `Open` | 打开子会话，恢复它自己的阅读位置；不新建分支或书签 |
| 侧栏切换 | `Open` | 恢复目标会话自己的阅读位置，不跳到来源 |

“返回来源”只依据分支关系，不依赖后退历史。子会话页顶部显示祖先路径（各祖先标题，可点击打开）与引用文字。侧栏按分支层级缩进显示：根会话按最近更新排序，子会话按创建顺序排在父会话之下；未命名的分支以引用文字作为显示名。

## 阅读位置与草稿

- **持有者：**`ReadingStateService`（Application）在内存保存每个 `(会话, 槽位)` 的最新值，页面读取以内存为准，因此离开后立刻重新打开也不会读到落后的数据库值；落盘按键防抖 500 ms，退出时在关闭数据库前全部写完。
- **阅读位置：**视口顶部所在的消息 ID、块序号，以及适配层细节（源文区块范围、同范围序号、块内字符位置）。滚动后约 200 ms 采集一次，离开页面时再采集。恢复时按“同一源块的同一字符 → 同一消息开头 → 会话末尾”逐级降级（需求 §6.3 允许回到对应段落）。打开时若有“返回来源”的定位请求，以定位为准。
- **草稿：**会话页输入框内容随输入更新到服务；发送成功清空并删除行。新会话页的草稿只保留在页面实例中（会话尚不存在）。

## 性能（E6）

`PerfSeed` 加入十层分支链，基准“为最深分支组装上下文”预算 300 ms（完整规模）。界面渲染基准随后补充。
