# 运行与工具（智能体平台第 2 期）

依据：[需求](../requirements.md) §10.4.4 与 §11 第 2 期验收（v0.17），[架构](../architecture.md) §15.3–15.7、§15.10–15.12，[待决定的问题](agent-platform-questions.md)（用户 2026-11-17 按建议通过 Q8–Q11）。本文记实现层的选择；产品行为以需求与架构为准。

## 1. 本期新的决定（待用户确认）

需求与架构里没有写定、本期必须选一个的地方。都按“简单、可逆、不改变已验收的行为”选；用户选了别的，相应代码随之改。

| # | 决定 | 理由 | 其他选项 |
| --- | --- | --- | --- |
| R1 | 回答的正文是序号 0 的一个 `text` 块，模型各次回复里的文字依次接在其中；工具块排在正文之后。界面把活动说明画在正文之上 | 来源锚点、侧栏摘录、检查点都按块序号定位；正文固定在 0，旧代码与旧回答都不受影响。§15.3 原文“块按发生顺序排列”改为此 | 按发生顺序交错排列（锚点与渲染都要按块重写） |
| R2 | 第 2 期回答正文里不加编号出处；“检索总结网络”找到的总结在步骤详情里列出，点击打开 | Q8 说出处只在本地工具需要引用时才在本期做；步骤详情已能“跳到对应总结”，编号出处随第 3 期网络搜索一并设计 | 本期就加 `citation` 块与 [n] 解析 |
| R3 | “检索总结网络”在内存中对本工作区当前版本的标题与正文按检索词打分（与附件相同的切词：词与 CJK 相邻字符对），不建 FTS5 索引 | 一个工作区的总结是几十到几百个，打分在毫秒级；索引要在总结的生成、编辑、删除、版本切换处都保持同步，需要迁移与触发器 | FTS5 表加触发器（总结数以千计时再做） |
| R4 | 每个成功的工具结果都存为资源（`origin = 'tool'`），不只是大的；交给模型的部分超过约 2,000 估算 token 时只给预览加编号 | 步骤详情要能打开每个结果；结果之后还能被“检索附件”查到；资源随会话删除，不另设清理 | 只存超过阈值的结果 |
| R5 | 只在工具有东西可查时提供它：会话链里有带文字的资源才提供“检索附件”，工作区有已保存总结才提供“检索总结网络”；两个都不提供时，回答与第 1 期完全相同 | 空的工具只会多花 token、诱使模型白查一次 | 总是提供两个工具 |
| R6 | 上限的语义：最多 8 次模型请求，其中达到任一上限后的那一次不提供工具；它计入请求次数，时长另给 1 分钟；一次回复里超出工具次数上限的调用不执行，以“未执行：达到工具调用上限”交还 | Q9 说“达到上限时最后再请模型作答一次”；把这次算进 8 次，用户看到的上限就是真的上限 | 第 9 次才是最后一次 |
| R7 | 第 2 期不改附件的规划：§15.4 “模型能调用工具时，超过可用空间四分之一的附件只发送摘要和句柄”推迟 | 第 1 期的发送方式刚经用户试用通过；改成“只发摘要”会让不调用工具的回答变差，值不值要看真实使用 | 本期就改 |
| R8 | 最后一次（不带工具的）请求保留运行里的工具调用与结果，不发 `tools`，另加一条系统说明“已达到本次运行的上限，请根据已有结果直接回答，不要再调用工具” | 只发 `tool_choice: "auto"` 才处处可用（model-capabilities §5），不能用 `"none"`；去掉工具结果则白查 | 发 `tools` 加 `tool_choice: "none"` |
| R9 | 设置 › 工具的上限可调范围：请求 2–32 次、工具调用 1–64 次、1–30 分钟、2 万–200 万估算 token；保存在偏好设置（`tools.enabled`、`tools.limits`），不需要迁移 | 防止误填成 0 或极大值；偏好设置已有同类的键 | 不设范围 |
| R10 | 推理内容只在同一运行的内存里保存并回传（`reasoning_content`），从不写入数据库 | DeepSeek、Kimi 等在工具循环里要求原样带回；推理内容不显示、不保存是现行规则（2026-11-06） | 存进步骤 |

## 2. 存储（迁移 v17）

| 变化 | 说明 |
| --- | --- |
| `run_step` | §15.3 的列：主键（`task_id`，`ordinal`），`kind`（`model`／`tool`），`state`，`ai_request_id`，`call_id`、`tool`、`risk`、`approval`，`target`，`result_resource_id`（`ON DELETE SET NULL`），`started_at`、`finished_at`、`error_kind`、`error_detail`；另有 `input`（工具步骤的参数摘要，例如检索词，供步骤详情与统计）。随任务删除 |
| `generation_task` | 加 `tools`（JSON：冻结的工具名称与定义哈希；空表示没有工具）、`run_limits`（JSON：四个上限的快照）、`run_limit_reached`（达到的上限，或空） |
| `resource` | 加 `produced_by_task`、`produced_by_step`（工具结果由哪一步产生；只是标识，不设外键：资源随会话删除，任务亦然） |
| 内容块 | `tool_call`：`text` 为一行可读说明（“检索附件：蒸汽机”），`data` 为 `{call_id, tool, arguments, risk}`；`tool_result`：`text` 为结果预览，`data` 为 `{call_id, status, detail}`，`resource_id` 为结果资源（出错时为空） |
