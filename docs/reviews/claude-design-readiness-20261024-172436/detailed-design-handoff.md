# 详细设计交接

**本文件不是开发授权。** 它说明详细设计能否开始、各模块需要什么输入、应产出什么，以及推荐的推进与验证顺序。依据为 [v2 需求](v2/initial-requirements.md)、[v2 架构](v2/architecture-discussion.md) 和 [审查报告](review-report.md)。

## 1. 能否开始

> **2026-10-24 更新：** 下列三项条件已全部满足（MW-C01–C04 已接受，U1–U3 已答复）。现在**可以进入详细设计**；U4 已于 2026-10-25 答复，没有待用户决定的产品事项。输入以 [v4 需求](v4/initial-requirements.md)、[v4 架构](v4/architecture-discussion.md) 为准，下文的 v2 章节号在 v4 中不变。

**原结论：可以有条件进入详细设计。** 条件（详见审查报告 §5）：

1. 用户接受或推翻 v2 中的四项 A 类补全（MW-C01 重试另存、MW-C02 引用清单与摘要归属、MW-C03 状态归属、MW-C04 首版不从总结直接分支）。
2. 持久化模型最先定稿，其他模块引用它的实体与引用清单。
3. U1–U3 在对应模块定稿前答复。

## 2. 各模块交接

“可立即开始”表示输入已足够；“需前置”表示依赖其他模块先定稿。每个模块的设计只需达到能指导实现、能写出验收用例的粒度，不要求先写出全部 SQL、类或方法签名。

### 2.1 持久化模型与存储（可立即开始，最先定稿）

- **输入：** 架构 §4、§4.1、§4.2、§12；需求 §8、§9.3。
- **职责：** Core 定义实体与规则；Infrastructure 实现 SQLite、统一写入队列、迁移、备份、恢复；Application 定义存储契约。
- **需产出：**
  - 表、主键、外键、唯一约束草案，覆盖 §4.1 全部逻辑实体；明确哪些规则由约束保证、哪些由事务内应用检查保证。
  - 事务清单：创建分支（会话＋来源＋祖先范围）、消息终态、版本采用／丢弃／设为当前／删除、无依赖会话删除、归档与恢复、布局保存、迁移。
  - 引用清单落到具体字段，并给出每类删除的检查查询。
  - 连接模型（单写入连接＋只读连接）、写入队列与检查点合并规则、修订号防回退规则。
  - 启动顺序：单实例占用 → 结构版本检查 → 备份 → 迁移 → 进入工作台或恢复页。
- **验收重点：** 临时库上模拟事务中断、迁移失败、备份失败、强制终止后重开；原库不被覆盖，不出现悬空引用。

### 2.2 应用生命周期与导航（可立即开始，与 2.1 并行）

- **输入：** 架构 §2.1、§2.2、§3.4、§12.3；需求 §6.1、§6.3、§9.3；D4–D6。
- **职责：** Desktop 的 Root／Menu／Content、ViewLocator、主 ViewModel、工作区运行期状态。
- **需产出：**
  - 导航请求契约（目标主区、目标内容 ID、意图），以及“返回来源”与“后退”的区分。
  - 跨主区跳转后的后退结果表（MW-C10），覆盖网络 → 总结 → 来源会话、侧栏切换、返回来源三条路径。
  - 工作区运行期状态对象的生命周期：创建、切换时保存与恢复、退出时丢弃（MW-C03）。
  - 退出与切换工作区的状态机，满足“可取消提示先于不可逆步骤”（MW-C09）。
  - 工作区最小管理（新建、切换、首次引导）的入口位置（MW-C11）。
- **验收重点：** 用课程三层导航路径和双工作区事件表逐步核对；不凭接口名称判定合规。

### 2.3 会话、消息与生成协调（需前置 2.1 的 Message／GenerationTask 部分）

- **输入：** 架构 §2.2、§4.1、§6、§7；需求 §6.2、§9.1–9.2；D1、D3；U1（已答复：已完成回答也可重新生成）；U4（已答复：重试与重新生成只限会话最后一条回答）。
- **职责：** Application 生成协调器、队列、并发槽；Infrastructure 的 Chat Completions 适配器。
- **需产出：**
  - 生成任务状态机：排队 → 运行 → 完成／停止／失败；重启时未结束 → 中断；排队中取消；终态后迟到分块丢弃。
  - 回答消息状态机及重试／重新生成的取代关系（MW-C01）；上下文组装如何选取“最新尝试”；同一提问各次尝试的查看方式。
  - 调度规则：全局两个槽、用户提问优先、压缩作为前置子任务时不占满槽位等待自身。
  - 协议适配器契约：内部统一请求与流式事件、取消、错误分类；不暴露供应商类型。
  - 生成中正文的内存持有与检查点节奏，ViewModel 订阅方式。
- **验收重点：** 用真实服务做长回答、取消、切换会话、双路并发、退出确认；杀进程后重启标为中断且不重发。

### 2.4 Markdown 渲染与来源适配（可立即开始，需尽早做技术验证）

- **输入：** 架构 §3.3、§5；需求 §6.2–6.3；D7；LiveMarkdown 小样 README。
- **职责：** Desktop 的 View／适配层；锚点格式由 Core 定义为不透明值加格式版本。
- **需产出：** 锚点与阅读位置的数据格式（含格式版本与渲染配置身份）；捕获、校验、恢复、拒绝流程；流式增长时阅读位置的保持；校验失败的消息级降级（MW-C13）。
- **验收重点：** 固定 Markdown 样本覆盖 D7 首版结构；macOS 与 Windows 11 实机；库版本固定后重启恢复。

### 2.5 分支与上下文组装（需前置 2.1、2.3、2.4）

- **输入：** 架构 §4.1 祖先范围、§6.1–6.3；需求 §6.2、§9.6。
- **需产出：** 祖先范围的继承算法；预算分配与选择顺序；上下文摘要的生成、复用、失效与归属（MW-C02）；超限时的用户提示；任务输入记录清单（MW-C16）。
- **验收重点：** A→B→C 后 A、B 继续追加，C 重建的输入不含后来内容；真实长会话中纠正、来源和指代是否保留。

### 2.6 总结与版本（需前置 2.1、2.3）

- **输入：** 架构 §8、§10；需求 §6.4、§7.1–7.2、§8.1；D1、D2；U2（已答复：阅读进度阈值或手动开关）。
- **需产出：** 节点、版本、候选、编辑草稿的状态机；采用基线检查与确认；删除当前／最后版本、设为当前的事务与提示文案（含“上一保留版本”规则，MW-C17）；节点标记推导（MW-C07）；阅读进度的计算方式、阈值与短正文的停留条件（MW-C30）、手动开关的位置；二次命名任务的过期检查。
- **验收重点：** 交换候选完成顺序、手改后采用、删除当前与最后版本、迟到命名结果；节点唯一、已读不被重置。

### 2.7 总结网络（需前置 2.1、2.6）

- **输入：** 架构 §11；需求 §7.3–7.4；D8；U3（已答复：新生成总结位置直接保存）；网络样例 README。
- **需产出：** 节点与来源边的投影查询（含经未总结会话的路径边）；布局模块输入输出与确定性要求；新节点位置直接保存的单行提交，以及参照内存还是已保存布局（MW-C12）；布局修订号与保存快照；保存失败与离开提示；视口规则；为后续拖动预留的边界说明。
- **验收重点：** 显式保存后重进恢复坐标、视口自适配；保存失败保留内存；保存期间继续改动不被误标为已保存；节点删除后保存不复活。

### 2.8 会话管理、归档与导出（需前置 2.1、2.6）

- **输入：** 架构 §9、§8.1；需求 §8.2–8.3。
- **需产出：** 删除检查与拒绝说明；主动归档与推导隐藏的表示；恢复并继续；系统后台任务的取消（MW-C14）；归档会话总结与深层恢复的方案（MW-C18，交互评审确认）；导出流程。
- **验收重点：** 归档父分支后子分支独立归档状态保持；删除受阻说明原因；导出不改变指针。

### 2.9 模型配置与凭据（可立即开始）

- **输入：** 架构 §7.2–7.3。
- **需产出：** 连接与模型配置的数据与界面；凭据服务契约与两个平台实现；凭据版本绑定与清理（MW-C15）；模型发现与连接测试的调用方式及是否占用生成槽。
- **验收重点：** 凭据服务锁定或不可用时阅读不受影响、请求明确失败，不降级明文。

## 3. 真正需要用户决定的事项

U1–U4 均已答复（见 [用户决定记录](user-decisions.md)），当前没有待用户决定的产品事项。

另有两项需要外部确认、不属于产品取舍：课程计数口径与 Root 等价性（老师，既有 MW-10）；四项 A 类补全是否符合用户原意（用户审阅）。

## 4. 实现者可自行细化的事项

不必回头问用户，只需在设计中写明并保持可调：

- 超时、检查点与草稿保存间隔、token 估算方法、压缩阈值、默认上下文容量。
- 布局参数、碰撞处理、视口缩放范围、动画时长。
- 具体类名、DI 容器、MVVM 工具包、表名与索引。
- 同名规范化规则（大小写、全半角、空白）。
- 总结阅读进度阈值与短正文的停留时长。
- 备份文件命名与保留数量、空间回收时机。
- 模型发现与连接测试是否计入两个生成槽。
- 错误文案与提示样式（需满足“不只靠颜色”与辅助功能名称）。

如果某个选择会产生新的费用行为、扩大范围或明显限制使用，再集中向用户说明。

## 5. 推荐的推进与验证顺序

按端到端功能切片推进，每一片都在真实环境中闭环，而不是先写完某一层。测试以真实集成和故障注入为主，单元测试只覆盖纯规则（祖先范围、节点标记推导、布局确定性等）。

| 阶段 | 内容 | 验收依据 |
| --- | --- | --- |
| S0 骨架与存储 | 四工程、Root／Menu／Content、ViewLocator、SQLite 打开／迁移／备份、单实例 | 课程三层导航路径走通；临时库迁移失败原库不变；第二次启动回到已有窗口 |
| S1 真实聊天 | 工作区、会话、消息、Chat Completions 流式、停止、检查点、凭据存储、自动标题 | 真实服务长回答；杀进程重启标为中断不重发；凭据锁定时可阅读 |
| S2 分支与返回 | 选区锚点、分支事务、祖先范围、返回来源、再次进入、普通切换、草稿、阅读位置 | 需求 §11 前四行在 macOS 与 Windows 11 实机通过 |
| S3 上下文预算 | 预算、压缩、摘要复用与失效、超限提示 | 真实长会话检查纠正、来源和指代；压缩失败不静默截断 |
| S4 总结 | 首次生成、候选、编辑、版本操作、已读、二次命名 | 需求 §11 总结相关行及补充场景 |
| S5 网络 | 投影、自动布局、视口、显式保存、失败处理 | 需求 §11 布局两行；保存故障注入 |
| S6 整理与收尾 | 归档、删除、导出、退出顺序、全量故障注入、Windows 全流程、课程交付检查 | 可靠性补充场景表全部通过；交付包大小与内容核对 |
| 价值验证 | 按需求 §12 的方法做延迟回顾比较 | 记录条件与结果，不外推 |

S2 完成即可做一次真实的多层探索试用；S4 完成后才能开始延迟回顾试用。装饰动效与手动拖动不进入上述阶段。
