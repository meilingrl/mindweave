**状态：五轮审查已完成，第四、第五轮连续无新增高价值问题；设计副本收敛，用户/老师待决和实际验证继续保留。** 所有输出仅在此 review 目录，未合并原版，未启动开发。

先看本报告前两节；准备逐项讨论时看 D1–D8。最新完整副本：[v6需求](v6/initial-requirements.md)、[v6架构](v6/architecture-discussion.md)。12个稳定问题见[最终状态表](ISSUES.md)。

## 先看判断

**保留当前产品方向与技术路线，下一步先确认少数行为取舍，再形成正式实施方案。** 现有结论已经能解释“从原文岔开、逐层返回、主动总结、日后回顾”；没有发现必须改换纯 Avalonia、四工程或 SQLite 的直接证据。需要补的是异步事件和持久引用交错时的边界，并把真实课程门槛落到可核查的职责。

这不等于可以无条件启动正式开发。首版的总结时机、版本可编辑范围、排队配置、单实例和后退范围仍有用户取舍；课程参照和计数口径也未固定。本文中的推荐是完整一致的副本提案，不是用户已经批准的新决定。

## 最值得先讨论的 8 个问题

| 顺序 | 问题及用户会遇到什么 | 当前建议／还缺什么 |
| --- | --- | --- |
| 1 | **总结时机与覆盖范围（MW-01）**：回答还在增长，点总结究竟包含哪段？ | 推荐先完成／停止，再接受总结；接受时冻结终态正文和背景。是否接受这一等待限制，需要你决定 |
| 2 | **候选与手改（MW-02）**：改一个候选错字，不应无意替换刚保存的当前版本 | 推荐一个总结任务、一个候选；候选／历史只读，先采用再编辑；操作绑定明确版本，编辑继承覆盖范围。限制及成本待你决定 |
| 3 | **持久来源与失败恢复（MW-06，关联 MW-04）**：保存失败后继续操作，不能留下“分支已保存，引用正文却没保存” | 补持久引用依赖的正文提交底线；失败原库不覆盖，旧任务不复活。单写入实例与恢复方式待决，实际故障验证未做 |
| 4 | **队列与终态（MW-03／04／12）**：排队后改API设置、停止后迟到分块、自动标题迟到，都应有唯一结果 | 推荐接受时冻结配置和输入；终态不可再增长、旧保存不可回退；标题不得撤销手动改名。队列快照取舍待你决定，机制未实现 |
| 5 | **后退、工作区和重启（MW-07）**：换工作区或看设置后，后退该回哪里？ | 主 VM 唯一内容栈已补课程契约。推荐只保留当前边界活动栈、切换重建最近页，重启只恢复最后有效页；这会失去跨界旧详情历史，需你决定 |
| 6 | **首版 Markdown 分支门槛（MW-09）**：表格／公式能显示，不表示能送出完整引用并准确返回 | 推荐先保证常见文字结构；表格／公式／图片等不承诺分支，明确拒绝不完整选区。需要你确认这些是否是首版必需；升级后锚点另验 |
| 7 | **课程工作量与交付（MW-10）**：聊天中很多会话不能自动算很多页面 | 已补原件映射；仍须固定 DailyPoetryA 参照版本、页面与类接口口径。不能凭四工程或测试数声称达标 |
| 8 | **网络是否帮助回顾（MW-08／11）**：没有总结根会话，也应找回原问题；不应先整理画布 | 补根群组＋完整路径入口，不制造空总结。无须拖动也能完成回顾；是否推迟手动拖动仅作范围选项，真实价值尚未测 |

递归祖先范围冻结（MW-05）、自动标题保护（MW-12）在副本内已补成必要不变量，通常不需要你挑技术实现。完整触发场景、证据强度、优先级和通过标准在 [累积问题清单](ISSUES.md)。

## 待你决定：选项、推荐与代价

这里列选择，不在需求正文同时采用互相冲突的方案。默认推荐只用于副本推演。

| 决策 | 背景与选项 | 推荐与代价 |
| --- | --- | --- |
| D1 总结是否可与当前回答同时进行 | A 等回答完成／停止；B 允许部分正文快照并准确表达后来追加 | **A**，首版范围与提示简单；代价是不能边看增长中的当前回答边总结。B 需保存可变消息的精确正文截点及更细新鲜度提示 |
| D2 候选数量及编辑范围 | A 一个候选、候选与历史只读、先采用再编辑；B 多候选或直接改候选但保持其候选身份 | **A**，降低版本管理成本；代价是再总结前先处理旧候选，修正候选需先采用。当前版本相对候选基线已变时，采用需要说明替换。B 更灵活但状态与入口增加 |
| D3 排队后改配置 | A 接受时冻结目的地／模型和输入；B 执行时采用最新设置并明确告知 | **A**，用户的一次发送有确定去向；代价是后来改设置不影响旧队列，必要时需取消重发，旧凭据失效可能报错。不会静默改送另一服务 |
| D4 同库多实例 | A 一个写入／调度实例，第二次启动提示使用已有实例；B 多写者＋共享调度＋冲突处理 | **A**，无需多窗口协作复杂度；代价是第二进程不能独立编辑。异常退出后仍必须能安全重开，不能靠删库解锁 |
| D5 切工作区／主区的后退 | A 当前边界一份活动栈，跨界重建目标最近页；B 主 VM 保管各边界运行期历史并切换活动栈 | **A** 作为最小首版提案；代价是短暂看设置或切工作区会失去旧详情后退历史。B 保留更多连续性，但要明确多个范围及切换恢复。两者都不能让导航服务另存业务栈 |
| D6 重启与退出保存失败 | 重启 A 只恢复最后有效页；B 恢复完整详情历史。失败 A 可重试退出或返回工作区；B 只留重试入口 | 推荐重启 **A**，状态少但旧后退历史不保留；保存失败推荐 **A**，可继续使用但旧任务保持取消，不自动重发。强制终止不保证最后检查点后的分块保留。这是原 §18 待决的延续，不是新批准 |
| D7 表格／公式等是否首版门槛 | A 首版常见文字结构，其他可读但不承诺可分支；B 将指定复杂结构纳入正式首版必验集 | 推荐先以 **A** 估算；代价是部分模型回答选区会被拒绝。若你的探索经常依赖表格／公式，应选 B 并先验证；不能为缩范围声称它们已不可行 |
| D8 是否缩减手动布局 | A 保留已确认拖动；B 推迟手动拖动及位置整理，保留稳定自动布局／查找／路径 | **不自动删范围**。若预算紧张，优先讨论 B；代价是暂不能手工摆位置，收益是减少画布状态管理。没有证据证明拖动有害或必需 |

数据库迁移方案、平台凭据后端、正式依赖锁版、上下文预算和布局算法属于后续实施设计与验证，不必让你逐个挑内部技术。课程侧另需固定参考版本与计数口径；若它影响达标或 Root 单窗口等价性的判断，应向老师确认。四工程不因示例两工程而自动违规，也不因此自动合规。

## 原结论与证据：哪些保留，哪些建议调整

- **继续保留：** 个人好奇探索定位；聊天是起点而非先维护图；会话树与总结网络分工；来源锚点／阅读位置／普通后退分离；终态文字才可分支；稳定总结节点、候选不自动覆盖、已读按版本；真实来源边与后续语义关联分开。
- **架构方向保留：** 纯 Avalonia、Core/Application/Infrastructure/Desktop 四工程、单 SQLite、视图外生成协调、单套API配置UI与连接／模型／协议边界、自有来源适配。未要求 Worklog 迁移或照搬原型工程。
- **建议调整／补全：** 上述 D1–D7 的完整行为提案；来源目标持久化、终态与旧保存屏障、递归上下文、版本提交、无祖先总结路径及过时标题保护。D8 只是可推迟项。
- **尚无本轮实测证据：** 正式 AI＋来源适配＋SQLite 集成、Windows、长文／两路流的性能、全 Markdown 结构、渲染升级引用兼容、生产恢复、课程数量／实际交付达标、延迟回顾价值。

两套原型原记录仍分别成立：Avalonia 聊天原型的当前 macOS 用户确认，与 LiveMarkdown 组件小样有限技术记录分开；原文的 31/31、8/8 是历史报告，本轮没有重跑。正式产品实现、课程验收和价值验证没有随本次审查自动通过。具体 [证据边界](evidence/verification-boundaries.md)、[固定版本官方核对](evidence/official-library-check.md)、[课程原件取证](round-1/verification-evidence-course.json)。

## 相对 v1 的实质变化

1. 把“生成开始固定范围”细化为推荐“接受时冻结”，补排队配置、终态、退出与旧保存顺序。
2. 把稳定总结节点补成有数量边界、明确可编辑对象与采用对象、原子当前指针的完整版本提案。
3. 明确事实、用户状态、派生图与界面偏好，补提交前外呼、来源目标持久化和无损恢复底线；单写者作为待决限制。
4. 补主 VM 唯一栈、统一目标／参数和真正渲染契约，明确推荐后退作用范围但不代你批准原 §18。
5. 补无已总结祖先的根群组／完整路径；分开渲染／引用／分支能力，给不支持结构与升级拒绝边界。
6. 补课程原件的门槛映射，保持参考数量未知；补自动标题的手改优先保护。

没有加入语义网络、推荐系统、复杂版本差异、多配置管理、备份产品或多窗口协作，也没有把手动布局从原已确认范围暗中删除。
