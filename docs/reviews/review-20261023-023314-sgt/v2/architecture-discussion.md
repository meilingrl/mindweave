## 1. 当前结论与边界

- 产品继续面向个人日常好奇与非专业领域专题探索，核心是从回答原文分支追问、准确返回，以及留下可回顾的总结。
- 第一版按主题工作区组织，降低会话和网络的复杂度；会话树与总结网络保持不同职责。
- 继续作为同一门课程的期末项目，满足 MVVM、Root／Menu／Content 导航、ViewLocator 或等效机制等课程要求。
- 继续以 **C# + 纯 Avalonia** 作为正式版架构讨论基线。本轮 macOS 核心交互原型已获用户确认通过，验证范围见第 9 节；尚未授权正式开发。
- UI 参考 Codex 的整体布局、侧栏与简洁状态表达；参考外观和交互不等于复制其内部技术实现。
- 四工程、SQLite、课程导航、生成协调、模型配置、Markdown、总结版本与网络交互方向已确认，详见第 10–17 节。本轮只沉淀文档，不开发或迁移 Worklog 代码。

## 2. 产品与界面组织

### 2.1 主题工作区

主题工作区组织一次或一类探索涉及的会话和总结。初期先进入主题，再查看该主题内的会话与网络，避免所有内容立即混在一张大图中。

一个工作区允许多个根会话。正式版采用一个本地 SQLite 数据库保存所有工作区；工作区仍是产品组织边界，不是独立数据库。

第一版图谱以已保存总结及真实探索来源关系为主；跨主题语义关联、自动分类和推荐探索仍是后续增强。

### 2.2 统一会话体验

根会话和分支会话使用相同的聊天界面与消息机制。分支的区别在于有父会话、来源消息和选区引用，而不是一套独立的聊天系统。

统一会话模型需要容纳进行中的回答。已完成消息、生成中的内容及失败或取消结果不能被简单当成同一种完成状态。

侧栏参考 Codex：以标题、层级、选中状态和必要的轻量标记组织，不把“生成中／已完成”作为每行常驻的文字标签。错误或需要用户操作的信息仍需清楚表达。

### 2.3 来源与阅读位置

- 来源锚点记录分支从父会话的哪条消息、哪段文字产生，属于持久的探索关系。
- 阅读位置记录用户在某会话当前读到哪里，可以持续更新。
- “返回来源”定位并提示分支入口；普通切换恢复目标会话自己的阅读位置。
- 从已有入口再次进入子会话不创建新分支或新书签。
- Markdown 原文包含格式标记，屏幕文字经过排版，二者位置不必一一相同；不能直接把显示文字偏移当作原文偏移。
- 已选 LiveMarkdown 加自有来源适配层；来源锚点与阅读位置分别维护，精度与验证边界见第 14 节。

## 3. 回答生成、切换与退出

已确认的行为：

1. 同一个会话同一时刻最多有一个进行中的回答；不同会话可以各自生成。首版全局最多同时执行两个 AI 请求，其余进入可取消队列。
2. 切换会话或界面不会自动停止原会话的回答；再次进入能够看到其最新内容。
3. 生成任务的生命周期不能依附于当前可见的聊天控件，否则切换界面可能丢失任务或状态。
4. 退出应用时，如仍有生成任务，提示用户；确认退出后停止生成，保存已经收到的内容，再退出。
5. 不要求关闭窗口后后台常驻。部分回答保留取消／中断状态，不伪装成完整回答。

由这些行为推导出的设计方向：生成协调应独立于视图实例，通过会话标识更新对应状态；UI 观察状态并发出操作请求。已确认的协调与保存原则见第 11、12 节；具体接口与保存间隔留给实施设计。

## 4. 课程架构要求与职责划分

课程原件：[期末项目与报告要求](<~/School/Courses/2026-Fall/全栈开发技术/Worklog/docs/期末项目与报告要求.docx>)。老师口头提出“不要做 Web”，需同时考虑，不能仅凭书面材料允许不同技术就判定 Web 路线合规。

| 要求 | 本项目应体现的职责 |
| --- | --- |
| MVVM | Model 表达数据；ViewModel 管理界面状态和交互命令；View 负责显示及必要的控件适配，后台代码保持薄 |
| 统一导航参数 | 导航层按统一契约传递参数，避免依赖具体 ViewModel；ViewModel 不直接依赖 UI 导航控件 |
| 服务接口与注入 | AI、持久化、导航及 UI 反馈等副作用通过接口访问，集中组装依赖，可替换测试实现 |
| Root／Menu／Content 导航 | 分别表达根窗口或启动切换、主区切换、详情推栈；由 ViewModel 维护相关状态，保留课程指定的三层服务化职责 |
| ViewLocator 或等效机制 | 根据 ViewModel 自动选择对应视图，而不是把页面类型判断散落在业务逻辑中 |
| Library／UI 分离 | 核心数据、服务契约和可复用逻辑与桌面 UI 分离，依赖方向明确 |
| 异步与 IO 服务化 | 网络和存储不阻塞 UI；取消、失败及保存结果有可观察行为 |

后续已选轻量四工程方案，ViewModel 位于 Desktop；导航映射见第 10、11 节。不为满足形式引入更多工程或通用框架。

课程还包含功能意义、页面和类／接口数量、报告以及源码资源包大小等要求。采用某框架或实现上述结构，不自动代表完成全部验收。

## 5. 三条技术路线的比较与选择

| 路线 | 主要收益 | 主要成本与不确定性 | 当前定位 |
| --- | --- | --- | --- |
| 纯 Avalonia | C# 与课程架构衔接直接；一套桌面界面体系；覆盖 Windows、macOS、Linux | Markdown 选区、原文映射、高亮和阅读恢复需验证；不能只凭可渲染 Markdown 判断可行 | 当前评估基线 |
| Avalonia + Web 内容区 | 可保留 C# 架构，并利用 Web 处理富文本和图形交互 | 两套界面体系及桥接；主题、焦点、滚动和状态同步；WebView 平台差异；课程接受度需确认 | 备选，未采用 |
| 全 Web 桌面应用，如 Electron + Vue + TypeScript | 富文本、选区和图形交互处于统一 Web 界面；可明确实现课程架构 | 桌面进程通信、资源占用、技术迁移；Vue 不自动等于完整 MVVM；“不要做 Web”的解释存在关键不确定性 | 未获课程适用性确认，暂不作为默认路线 |

讨论中曾基于交互适配性优先推荐全 Web 路线；在补充老师的口头限制后，当前选择改为先评估纯 Avalonia。打包成桌面程序不能自动绕过老师的技术限制。若未来重新考虑 Web 路线，需要澄清老师限制的是浏览器网站还是 Web 主界面技术。

三条路线都可能做出统一、精致的 UI。纯 Avalonia 不等于界面粗糙，混合方案也不必出现可见的拼接边界；实际成本需要验证，不能从技术名称推定效果。

### 5.1 跨平台范围

第一版评估优先覆盖 macOS 开发环境和 Windows 演示环境。Linux 可作为后续目标，不扩大当前验证范围。不同系统及 CPU 架构需要相应发布产物，并分别验证输入法、快捷键、缩放、窗口及文本交互。

纯 Avalonia 和 Electron 均支持三大桌面平台，但支持的系统版本取决于所选版本。混合方案还取决于具体 WebView 后端及运行依赖，不能从外壳跨平台推导出内部行为完全一致。

### 5.2 当前选型状态

已选：纯 Avalonia、四工程、本地 SQLite、单套 OpenAI 兼容接入、LiveMarkdown 加来源适配层。具体职责及扩展边界见第 10–17 节。

待定：正式版最终依赖版本、网络布局算法与控件细节、数据库迁移和凭据后端、状态恢复细节。Worklog 未完成复用盘点，不承诺复用比例。原型依赖版本是验证依据，不自动成为正式版依赖锁定。

## 6. 对参考项目的结论

[Starward](https://github.com/meilingrl/Starward) 是 C#／WinUI 桌面应用，不是全 Web 界面路线。它可以作为产品与界面参考，但不能直接作为课程架构合规模板。

当次检查发现，主视图后台代码承担状态、页面导航及更新检查；服务注册主要使用具体业务类，页面通过服务定位获取服务；主导航使用 Frame.Navigate。这些与课程强调的薄 View、ViewModel 职责、接口注入以及三层服务化导航有差距。工程成熟度与课程指定结构是否符合是不同评价维度。

这是对已检查代码路径的静态判断，没有运行项目，也没有完成其课程工作量和交付要求的全面验收。

## 10. 已确认：轻量四工程

| 工程 | 职责与依赖 |
| --- | --- |
| Core | 工作区、会话、消息、来源、总结等模型和规则；不依赖 UI、数据库或供应商 SDK |
| Application | 用例、上下文组装、生成协调、总结操作及所需服务契约；依赖 Core |
| Infrastructure | SQLite、AI 协议适配、凭据访问；实现 Application 所需接口 |
| Desktop | Avalonia Views、ViewModels、导航、控件适配和应用启动组装 |

Desktop 启动入口组装基础设施，ViewModel 通过用例与服务接口工作。选区命中、文字几何、高亮和滚动属于 View／适配层，不为形式上的 MVVM 强塞进 ViewModel。

只在存储、AI、导航等实际替换边界抽象；不引入通用命令总线、逐类接口或复杂仓储框架。原型不直接扩建成正式产品；正式开发尚未授权。

## 11. 已确认：存储与课程导航

采用单个本地 SQLite 数据库，通过轻量 Microsoft.Data.Sqlite 访问，不以引入 EF 为前提。保存工作区、会话、Markdown 原文消息及状态、来源锚点、阅读位置、草稿、总结和版本、布局与工作区最近状态。稳定 ID 用于关联；不把控件实例或供应商 SDK 对象写入数据库。

- 分支会话与来源记录在同一事务中创建，避免只有一半成功。
- 流式显示与落盘节奏分开；定期保存部分内容，完成、取消、失败等终态及时保存；写入统一协调。
- 凭据通过独立服务管理，不作为普通明文字段放入业务数据库；各平台具体后端待选。
- 网络节点和关系由总结及真实会话来源推导；只额外保存布局与视口，不维护第二份独立图数据库。
- 数据库版本迁移、损坏恢复和多实例策略尚待细化，原型 JSON 不是正式存储方案。

| 导航层 | 对应功能 |
| --- | --- |
| Root | 初始化／恢复到主工作台的切换 |
| Menu | 探索、总结网络、设置等主区切换 |
| Content | 具体会话、子会话、总结详情及详情访问历史 |

主题工作区是作用范围，不强行多套一层导航。切换工作区恢复其最近内容，也不取消其他工作区正在进行的生成。导航参数传稳定 ID 与操作意图，不传控件或 ViewModel。

“返回来源”依据分支关系与来源锚点；普通“后退”依据访问历史，两者不能混用。ViewLocator 根据 ViewModel 选择 View；三层导航通过服务契约访问。

### 11.R 审查建议：数据职责、提交与恢复（MW-06、MW-07）

以下为副本提案，不把 §18 原待定恢复问题变成用户批准。

| 数据类别 | 权威与恢复边界 |
| --- | --- |
| 消息原文／状态、分支与冻结来源范围、总结节点／完整版本／当前采用指针、请求身份与配置身份 | 事实数据；保持稳定关联，不用图或控件重建猜补 |
| 版本已读、草稿、阅读位置 | 用户状态，虽不是知识事实，也须保留已确认的持久恢复承诺；草稿不可当可丢缓存 |
| 来源边／中间路径、根群组、是否有未纳入内容 | 从事实推导，首版不另存独立图真相 |
| 布局坐标、网络视口、选择、最后工作区／页面 | 可恢复的界面偏好；失效时回安全入口或重建，不阻止读取仍完整的内容 |

除已确认的分支＋来源事务外，建议发送的用户消息＋对应任务记录在外部请求前提交；总结节点／版本＋当前指针的建立、手改保存、候选采用／丢弃为各自完整原子操作。UI 可见的“已保存”只表示提交成功；旧检查点不能覆盖较新内容或终态。全局统一协调写入不替代这些业务不变量。保存部分流内容不要求逐 token 落盘。

正式迁移／打开失败不以新空库覆盖原库；保留原文件并报告。陈旧页面或视口可安全降级，事实来源失效明确报告，不能猜补。迁移方案、凭据后端与用户可用的恢复模式仍待定，本轮不设计备份产品。推荐首版一个数据库一个写入／调度实例，第二实例提示使用已有实例；异常退出后须可重新打开，不以删除数据库解锁。此限制待用户决定。

课程 P19–20 的三层服务化导航须有真实职责：Root 管根／窗口启动生命周期，Menu 管主区，Content 管详情推栈。统一目标标识与参数入口实际参与导航；主 ViewModel（可对应 MainViewModel.ContentStack／PushContent／GoBack）是唯一业务内容栈权威，服务与 View 不另建栈；ViewLocator 实际由 ViewModel 渲染 View。原件将目标常量与主 VM 栈归属写得具体，不仅检查三个接口的名称。Root 若仅用单窗口初始化状态，仍需说明等价生命周期并在课程接受度有疑问时向老师确认；本轮不判为已合规。

工作区／主区后退边界推荐：仅保留当前工作区和 Menu 范围的一份活动内容栈；切换边界时重建目标最近页作为入口，不保留可跨界弹出的旧历史。返回来源按来源关系导航，不能伪装为 GoBack。重启恢复最后有效页而非整个栈仍待用户确认。这一推荐待用户决定，未同时采用全局跨工作区栈方案。

## 12. 已确认：上下文与生成生命周期

子会话使用创建时冻结的来源范围，加上自身消息。保存来源引用及截止点，不为每个子会话复制全部祖先历史。必要背景包含选中文字、来源回答和相关前置问答；不包含兄弟会话、其他根会话或父会话后来新增的消息。

上下文预算优先保证当前问题、选区与直接来源、近期子会话问答，再考虑较早祖先。历史过长时可以压缩，并以轻量方式说明；保留原始记录，不能静默截掉必需来源。具体预算计算与压缩触发条件留待实现设计。

- 生成由 Application 层协调，生命周期属于应用，不属于当前 View。
- 每个会话最多一个回答；全局最多两个 AI 请求，其余可取消排队。用户提问优先于自动标题和总结任务。
- 切换页面／会话／工作区不取消生成。正在增长的回答完成或停止后才能用于创建分支，旧回答不受限制。
- 失败或取消保留部分内容并标明状态；重启后未正常结束的请求标为中断，不自动重发。
- 退出时提示正在进行的任务，确认后停止并保存；不后台常驻。
- 网络分块、UI 刷新和磁盘保存采用各自节奏，不复制原型固定分段输出的演示节奏。

### 12.R 审查建议：时序契约（MW-01、MW-03、MW-04、MW-05）

- **接受／排队／执行：** 推荐在接受操作时冻结目的连接、模型参数与输入范围，先提交本地消息与任务记录，再入队；执行只领取名额，不重读活动配置来改变目的地。界面排队状态与取消对象明确。持久记录不包含明文凭据；凭据独立服务提供本次运行所需访问，凭据变化不能让旧任务静默转向新目的地，失败明确报错、不自动兜底。具体凭据生命周期仍随后端设计确认。
- **调度：** 两名额覆盖回答、总结和标题。用户提问只在领取空闲名额时优先，不抢占运行任务，不引入抢占恢复框架。单会话一个回答和一个总结任务的限制分别检查；推荐有待处理候选时不接收新的总结生成。
- **冻结背景：** A→B→C 的 C 必须继承 B 已冻结的 A 范围，再加 B 截至 C 分支点的范围；不得读取 A 当前末尾。上下文压缩不改写原来源边界。无需为每个分支复制全部祖先。
- **总结范围：** 推荐当前会话存在排队／生成中的回答时不接收总结请求；完成／停止后再发起。接受时锁定终态消息实际文本和背景范围，停止／失败的部分回答保留不完整状态。之后继续聊天不扩大该任务范围。此体验取舍待用户决定。
- **终态与迟到事件：** 每次生成具有明确身份；一旦对外允许从已停止回答分支，同次生成不得继续追加，旧保存不得回退状态。UI、任务和落盘按同一已接收状态推进，具体同步手段在实施中决定。
- **退出：** 确认后先关闭新操作与队列启动入口，再收束运行任务、将排队任务记为未执行取消、保存最后接受的内容及终态。不把取消释放的名额给下一任务。保存失败的操作窗口保留／重试按 §18 推荐待决；重启将非终态记录标中断，绝不自动重发。强制终止只能恢复最后提交检查点，不承诺零分块丢失或供应商恰好执行一次。

## 13. 已确认：模型来源与可扩展配置

用户填写自己的 API。首版桌面直接访问服务，不建设代转发后台、账户或计费系统。配置界面先管理一套 OpenAI 兼容 Chat Completions 接口，支持文字与流式输出；先验证一个实际服务，不承诺所有兼容端点都完全一致。

首版配置包括名称、地址、密钥、模型 ID；允许手填模型 ID，并保留高级上下文预算设置。连接测试由用户显式触发，可能产生少量调用费用。首版各任务使用同一活动配置，不自动切换到其他服务兜底。

从数据与接口上分开：

- 服务连接：稳定 ID、名称、地址、协议类型、凭据引用。
- 模型配置：稳定 ID、服务连接 ID、模型标识、预算／能力和参数。
- 协议适配器：转换内部统一请求与流式事件，不把供应商 SDK 类型暴露给 Core／Application。
- 模型选择策略：决定任务使用什么配置，与请求执行分离。

供应商不等于协议。数据从一开始允许多个连接与模型，首版 UI 只管理一套；以后添加供应商、协议和按会话选择模型应局限在对应边界，不重写业务模型。运行中的请求使用不可变配置快照，产物记录实际模型与配置身份；中途改设置不改变已发出的请求。不做动态插件市场。

## 14. 已确认：LiveMarkdown 加来源适配层

采用 LiveMarkdown.Avalonia 渲染 Markdown，自有适配层负责选区捕获、来源验证、高亮与定位。业务数据不绑定控件实例，来源不确定时明确失败，不靠搜索相同文字猜位置。

[独立组件小样](../../../prototypes/livemarkdown-chat/README.md) 使用 .NET SDK 10.0.402、Avalonia 12.1.4、LiveMarkdown.Avalonia 2.5.1，与旧 Avalonia 11 原型隔离。已有 macOS 实机证据包括重复词正确定位、跨格式跨两段选择、正文变化拒绝恢复、追加及窄窗重排、关闭进程后恢复选区；该轮 Debug／Release 均 8/8。此次文档整理未重跑测试。

当前验证的富文本锚点是“源文区块范围＋块内显示位置＋引用与完整性校验”，不是通用 Markdown 精确原文字符映射。只有源块与显示文字完全相同才能记录精确原文偏移。正文前缀和所选块未变时允许追加；追加导致旧块格式变化时拒绝恢复。

来源锚点与持续更新的阅读位置分别维护。表格、公式、复杂 Unicode、嵌入控件、Windows 实机及长文性能仍待验证；不把组件小样称为完整聊天或正式版验收。库在后台解析完整 Markdown 快照，再增量更新视觉控件，不称为增量解析器。

### 14.R 审查建议：支持面与锚点兼容（MW-09）

采用库不等于自动获得所有结构的持久引用。以固定版官方资料与小样源码为证据：[核对记录](../evidence/official-library-check.md)。分别列出“可阅读渲染／可复制引用／可来源分支”，推荐首版分支目标为段落、标题、列表、引用、代码、粗体／链接／行内代码文字与跨段。未获验证前不写成已支持。表格、公式、图片或嵌入内容暂不承诺分支；引用含无法解释的占位符、漏字或拼接顺序不明时拒绝创建，保留原文可读，不改用全文搜索猜来源。复杂 Unicode／双向文字保留为样本验证项。该目标面仍需用户确认是否满足其场景。

持久锚点区分格式版本与解析／渲染配置身份，稳定消息、引用与原文独立保存。库或配置升级后不能用新布局直接解释旧偏移；要么校验恢复原选区，要么明确无法精确定位并保留原来源。重建页面／选用新控件不应销毁来源事实。仅在锁定正式版与实际变更渲染版本时补兼容样本验证，不为此要求现在重跑原型。

## 15. 已确认：总结节点、版本与已读状态

第一版一个会话对应一个稳定总结节点，节点下保存版本。首次生成与后续更新采用不同流程：

1. 首次生成成功后直接保存为未读节点，不强制预览或打开，用户可以继续聊天。
2. 再次生成保存为候选版本，当前采用版本保持不变。用户之后打开候选，选择采用或丢弃；不能静默覆盖手写修改。
3. 手动修改标题／正文，在保存时形成版本，不为每次按键生成版本；首版提供简单历史，不做复杂差异比较。

阅读状态与采用状态独立。打开某个版本的正文才标记该版本已读；采用已经读过的候选不会把它重置未读。查看旧版本不表示读过新版本，参与原会话也不表示读过总结。

生成开始时固定消息范围，仅总结当前会话及理解所需的分支背景，不自动汇总所有后代。后续消息提示“后续内容未纳入”，与未读状态分开。

节点保存稳定 ID、工作区、来源会话、当前版本；版本保存标题、正文、覆盖范围、时间、生成或手动编辑来源以及实际模型信息。节点身份不因更新而变化，不让版本在网络里堆成重复节点。

### 15.R 审查建议：版本竞争与候选边界（MW-01、MW-02）

推荐每会话一个总结任务、一个待处理候选；未处理候选前不接收下一次生成。节点对来源会话唯一，重复操作不产生第二节点。首次成功建立节点与初始采用版本一次提交；后续成功只登记候选，不切换当前指针或正在阅读的正文。

所有手改、采用、丢弃针对明确版本身份；手改保存成为当前版本并保留旧版本，候选记录其基线。用户正在看 C1 时操作只作用 C1。若当前版本相对候选基线已改变，采用前说明将替换当前版本且历史仍可取回，再确认采用；不静默自动合并。采用已读候选不重置其已读。候选数量限制与额外确认是审查提案，仍需用户决定。

## 16. 已确认：总结网络的展示与交互

网络限定当前主题工作区，允许多个根探索群组。只展示已保存总结；没有总结的会话仍从侧栏访问，不制造空白总结节点。第一版边只表示真实探索来源，不生成 AI 猜测的语义关系。

若中间父会话没有总结，可连接最近的已总结祖先与后代，但必须用不同线型并标明“经 1 个未总结会话”等信息，允许查看完整路径，不能冒充直接父子关系。

| 操作 | 行为 |
| --- | --- |
| 单击节点 | 选中，显示标题、来源、时间等简要元信息；不展示完整正文、不计已读 |
| 双击或“打开总结” | 进入主内容区的总结正文页，标记打开的版本已读 |
| 回到来源会话 | 恢复该会话阅读位置，继续提问；需要查看分支入口时另走返回来源语义 |
| 从详情回到网络 | 保留原来的缩放、平移与选中节点 |
| 拖动空白／滚轮 | 平移／缩放 |
| 标题查找／显示全部 | 聚焦匹配节点／适配全图视口 |

节点采用圆点与标题、选中描边、未读标记；状态不只靠颜色区分。候选更新提示与未读标记分开，后续未总结消息作为元信息。节点大小不暗示理解程度或会话长度。

**【审查建议 MW-08】** 即使不存在已总结祖先，每个节点仍有根会话群组信息及完整来源路径入口；从中可打开任何未总结会话。共享未总结根的兄弟总结只共享群组，不伪造父子边。路径边只是从事实投影，根标题不是一个虚构总结节点。

## 17. 已确认：网络布局与实现边界

采用稳定的自动布局，按真实探索来源组织群组，不让力导向模拟持续运动。保存节点位置，新节点尽量放在来源附近；全图重新整理由用户显式触发。允许拖动节点调整观感，但不发展成完整图编辑器。

- Application 提供节点、来源边及中间路径数据。
- 布局模块输入图结构、输出坐标，与具体 UI 控件分开。
- 网络 ViewModel 管理选择、搜索与视口状态。
- 原生 View 初期绘制边，并使用普通 Avalonia 控件展示节点；只在实际规模或性能要求出现时再调整绘制方式。
- 保存布局与视口，打开总结使用主内容页面，不用拥挤弹窗承载长文。

尚未选定布局算法／图形库，也没有实现正式网络。语义边、跨主题网络、推荐探索和大规模优化仍为后续增强。
