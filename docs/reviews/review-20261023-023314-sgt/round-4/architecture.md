## MW-06 原反例重放

| 事件 | 推荐规则允许的事件后状态 | 不变量判断 |
| --- | --- | --- |
| 源回答最新正文 T1 在内存，磁盘只有 T0 | T1 尚不能作为已持久引用的完整依据 | 没有把内存终态误当已保存；明确 |
| 确认退出、停止回答，最终保存失败 | T1 与取消状态留在内存；窗口保留，持久状态仍只保证最近成功提交 | 原有失败保护不变 |
| 返回工作区，从 T1 末尾文字创建分支 | 必须先成功提交相应 T1／终态／冻结边界，或将它们与新分支来源一起提交 | 不能再只提交分支＋锚点而遗漏源正文 |
| 依赖提交失败 | 不成立一个对外声称已保存的分支来源；保留未保存内容及错误，不猜补关系 | 原反例中的“新来源保存成功、源文仍只有 T0”不再是合法结果 |
| 依赖和来源提交成功后立即强制终止 | 重启可读取建立来源所需的 T1／终态／边界和该引用 | 因引用而必需的文字已纳入持久承诺；不依赖下一次流检查点 |
| 引用提交前强制终止 | 只保证既有成功提交数据；不能声称新分支已保存 | 允许最近未提交操作丢失，与强制终止边界一致 |

结论：同样的故障顺序现只留下“依据齐全后成功”或“不声称保存成功”两类合法结果。没有必要规定具体 SQL、复制祖先正文或增加备份功能。

## 多消息范围与总结来源

| 来源组合 | 推演 | 判定 |
| --- | --- | --- |
| 引用需要 m1、m2、m3，三者所需正文／终态／边界都已提交 | 来源记录可以单独提交 | 齐全；无需重复写入全部文本 |
| m1 已提交，m2／m3 最新所需状态仅在内存 | 新引用提交前补齐缺失依据，或与引用共同提交 | 只保存最直接来源 m3 不能代替整个引用范围；规则已覆盖 |
| 补齐 m2 成功，补齐 m3 失败 | 可以保留已成功提交的消息事实，但新引用不得被声明保存成功 | 不要求把此前独立成功的事实写入回滚掉；要求来源依赖完整 |
| 总结已生成，但其冻结范围含尚未提交的终态消息 | 保存总结版本及其持久来源也受同一依赖条件限制；失败不能形成伪成功成果 | 生成成功与保存成功分开，不必重新调用模型来解决存储失败 |
| C 的背景依赖 B 的冻结 A 范围及 B 自身消息 | 持久来源的全部引用依据均须可恢复；可复用先前已提交边界和正文 | 递归冻结与依赖提交相容，不要求每个子会话复制所有祖先 |

结论：规则没有只保护单消息锚点而遗漏总结或多级范围。其安全性质足够明确；具体实现如何确认依赖齐全仍应在正式实施后验证。
