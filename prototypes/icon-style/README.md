## 现状盘点

**图标。** `Themes/Icons.axaml` 有 32 个 16×16 的填充路径：直角、尖角斜接，线条由 1.4–1.5 宽的矩形拼成，粗细接近但不统一（`Rename`、`Link` 等用斜线拼接，`Sun` 的光芒是平头矩形）。另有 **10 处图标直接写在视图里**，不在 `Icons.axaml`：总结网络工具栏的保存布局、显示全部、缩小、放大、整理布局、列表；总结页的查看当前（左箭头）、编辑（铅笔，与 `IconRename` 不同）、改名（“T”形，与 `IconRename` 也不同）与版本菜单的下载箭头。（保存布局旁的小勾、已读切换的圆环是状态标记，未列入。）统一替换时应把这 10 个也收进 `Icons.axaml`，并决定“编辑／改名”是否只用一个铅笔。每个图标的使用位置见 `icons.js` 的 `USES` 与对照表右栏。

**显示尺寸。** 图标几乎都比 16 小：侧栏导航与多数工具栏 13–15 px，缩放按钮 12，菜单箭头 9，只有一处 20。线宽在 16 格中设定后随尺寸缩放，所以 1.5 格在 13 px 时实际只有 1.22 px。

**圆角（`Styles/*.axaml`）。** 按钮 6（`nav`、`primary`、`secondary`、`quiet`、`entry`），焦点环 6 或 9；卡片、选区操作条、分段控件、选择条 8；输入框 12；菜单 10、菜单项 6；对话框 12；小标签 `badge` 9（高 18，近似胶囊），建议名称的小块 12；问题气泡 14；停止按钮 17（圆形）；工作区选择框 8；首页图标块 28。共有约 12 种取值（1、1.5、2、4、5、6、7、7.5、8、8.5、9、10、12、14、17、28）。

**线宽。** 应用内自绘线条：侧栏提醒圆点描边 2，转圈 `ActivitySpinner` 自绘，其余边框 1、焦点环 2。

## 三个方向

| | A · 圆润描边 | B · 柔和双色调 | C · 现有形状，只改圆角 |
| --- | --- | --- | --- |
| 做法 | 按中心线重画，圆头、圆角连接，线宽 1.5 格（可调到 1.75） | 与 A 同一套线稿；主体形状加 22% 透明度的同色填充，次要线条 55% | 保留现有填充路径，只把外角与连接处倒圆（预览用 SVG 滤镜模拟，约 0.75 格半径） |
| 观感 | 最轻、最圆，接近 macOS／现代桌面应用的通行风格 | 更柔和、有“分量”，选中与未选中的区别更明显 | 与现在最接近，差别要放大才看得出 |
| 小尺寸（12–13 px） | 1.5 格偏细（1.2 px），1.75 格更稳 | 填充让小尺寸更易辨认，但 100% 缩放下浅色填充显得发灰、略脏 | 与现在相同，清楚但仍显硬 |
| 深色主题 | 清楚 | 填充在深色下偏暗，层次变弱 | 清楚 |
| 危险色、强调色 | 同色描边，正常 | 红色、强调色的淡填充显得像“禁用”状态 | 正常 |
| 工作量 | 42 个已在本原型画好；需要把描边转为填充（见“实现”） | 同 A，再加填充层与透明度，图标需要两层 | 需要逐个手工重画圆角（滤镜只是预览，不能直接用） |
| 是否回应“生硬” | 是 | 是 | 只部分回应 |

A、B 的情境图同时用了建议的较柔圆角（见规则）；Current 与 C 保留现有圆角。这样 C 也代表“只动图标、不动控件”的最小改动。

## 建议：A（圆润描边），小尺寸用 1.75 线宽

理由：

1. 用户的问题是“生硬”。A 的圆头与圆角连接改变最明显，又不增加视觉重量；C 的改动在原尺寸下几乎看不出来。
2. B 的填充在 13 px、100% 缩放下发灰，红色与强调色的淡填充像禁用态；它更适合 20 px 以上的大图标（例如首页图标块），可以只在那里用。
3. A 的一套线稿可以同时服务 B，以后要给大图标加填充不必重画。

需要用户看的点：13 px 下 1.5 与 1.75 哪个更合适（`sheet-*` 表中两列并排，`?stroke=1.75` 可让情境图用 1.75）；建议圆角是否太圆。

## 选定方向的规则（A）

**图标**

| 项 | 规则 |
| --- | --- |
| 网格 | 16×16，作图坐标取 0.25 的倍数；内容在 1.5–14.5 之内（安全边 1.5 格），细小的附加标记（如 `Sparkle` 的小十字）可到 14.75 |
| 线宽 | 中心线描边。显示 ≤ 14 px 时 1.75 格，≥ 16 px 时 1.5 格（实际约 1.3–1.9 px）；同一行工具栏内用同一线宽 |
| 端点、连接 | 一律圆头（round cap）、圆角连接（round join），不用尖角斜接 |
| 形状圆角 | 大于 8 格的矩形圆角 2（侧栏框 2.25、选择框 2.5）；4–5 格的小方块 1.25–1.5；扁条（如归档的盖子）1.25 |
| 间距 | 平行线中心距至少 2.5 格（留出 ≥ 1 格空隙）；嵌套形状之间至少 1 格空隙 |
| 实心元素 | 只用于本来就是“块”的东西：停止方块（9×9，圆角 2.25）、列表圆点（半径 1）；其余都是线 |
| 颜色 | 一个图标只用 `currentColor` 一种颜色，由按钮或导航状态决定（`NavIcon`、强调色、危险色） |

**控件圆角**（建议；改动属于界面观感，需用户确认）

| 对象 | 现在 | 建议 |
| --- | --- | --- |
| 按钮（`primary`、`secondary`、`quiet`、`nav`、`entry`）、侧栏行、菜单项、输入框 | 6 | 8 |
| 焦点环 | 6 / 9 | 控件圆角 + 3（外扩 3 时）或同控件圆角（贴边时） |
| 卡片、选区操作条、分段控件、提示条 | 6–8 | 12 |
| 菜单、浮层 | 10 | 12 |
| 输入框（会话底部 `composer`） | 12 | 16 |
| 对话框 | 12 | 14 |
| 小标签、建议名称小块 | 9 / 12 | 胶囊（高度的一半） |
| 圆形按钮（停止）、首页图标块 | 17 / 28 | 不变 |

取值收敛为 4、8、12、16 与胶囊／圆形，替代现在的十余种。

## 实现说明（选定后）

- Avalonia 的 `PathIcon` 只填充，不描边。可行做法：在 `Icons.axaml` 保存中心线路径，加载时用 `Geometry.GetWidenedGeometry(Pen)`（Avalonia 12.1.4 有此 API）以圆头、圆角的笔转成填充几何，现有 `PathIcon` 用法不变；或用 `Path` + `StrokeThickness`/`StrokeLineCap`/`StrokeJoin`，但要改所有用到图标的模板。线宽要随显示尺寸选 1.5 或 1.75，因此转换时可生成两套资源，或按尺寸选择。**以上未在 Avalonia 中实际验证**，包括 `GetWidenedGeometry` 对圆头的处理与渲染效果。
- 本原型的截图由 Chrome（Skia）渲染，与 Avalonia（同为 Skia）应接近，但抗锯齿与 Windows 的像素对齐可能不同；替换后需要在两种平台、100% 与 200% 缩放下各截图确认。
- 测试里若有按图标资源键查找的断言，键名保持不变（`IconSparkle` 等），只换几何。

## 许可

全部 42 个新图标是本原型按上述规则自行绘制的，没有复制任何开源图标集的路径，因此不需要第三方许可或署名。参考了 Lucide 一类图标集的通行做法（圆头、圆角、留安全边），这只是风格，不是复制。
