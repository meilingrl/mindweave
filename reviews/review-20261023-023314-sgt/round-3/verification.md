# 第三轮独立实现、验证与课程审查

输入为 [v3 需求](../v3/initial-requirements.md)、[v3 架构](../v3/architecture-discussion.md) 与 [第二轮裁决](../round-2/report.md)，并核对 v2→v3 增量。本轮未读取其他第三轮意见，未运行原型、构建或测试，未访问用户应用数据或扩展官方研究。以下全部是静态流程推演，**不是实机、数据库、网络或课程验收结果**。

结论：三个要求的流程反例在 v3 推荐规则内均能得到一致解释；新增候选只读、退出失败恢复与标题保护没有升级历史证据。本轮新增高价值问题 **0 项**，不新增 MW 编号。可以作为本审查方向的一轮收敛，但待用户决定、待老师确认、待实施验证仍分别存在。

## 流程一：普通 Markdown、表格/嵌入选区与旧锚点重建（MW-09）

**具体输入与动作：** 会话 A 的终态回答包含“蒸汽机运行；**蒸汽机**继续运行。”，下一段有链接与行内代码。用户选第二处“蒸汽机”，再试跨格式跨段选区，保存分支 B；随后切到其他页面、销毁旧控件，再打开 A 并返回来源。另一条回答包含表格与图片/嵌入结构，用户从普通文字拖选穿过该结构；最后设想渲染配置升级后再打开同一旧锚点。

| 步骤 | v3 的纸面期望与验收标准 | 缺少的实际证据／降级 |
| --- | --- | --- |
| 普通段落显示 | 显示文字可读，格式标记不冒充显示坐标；段落、标题、列表、引用、代码等是推荐目标面 | 目标面不等于所有结构已有证据。正式锁版后须逐结构核对真实显示，不能把本表当测试通过 |
| 重复词与跨格式引用 | 捕获第二处词及真实选区顺序；送入模型的引用等于所见选中文字，不把 LayoutText 坐标当精确原文偏移，不发送非预期占位或漏字 | 两原型有相关有限历史记录；正式消息身份、跨格式引用组装和完整链路尚未验证 |
| 创建 B 并返回 A | 仅在正确引用与可验证来源均成立时创建分支；持久来源关联到 A 的明确消息与锚点；返回时定位第二处，不搜索并误选第一处 | 正式 SQLite 事务、真实模型上下文、当前正式控件适配没有运行证据 |
| 表格/嵌入选区 | “可渲染”“可复制引用”“可分支”分开判断。表格/公式/图片/嵌入暂不承诺分支；若不能形成完整可靠引用，就拒绝创建，保留原文可读，不把失败引用发给模型、不制造成功分支 | 当前没有这些结构的完整引用/来源证据。保留可读原文不意味着本轮已证明每种图片/公式都能绘制；渲染不可用时仍须保留原文阅读入口，不能把“未承诺分支”扩成保证高级渲染 |
| 同配置销毁/重建 View | 来源事实不含旧控件实例；同一消息、正文和渲染配置下，以保存记录重建后校验来源，成功才恢复选区/高亮 | 既有组件文件用例与桌面记录不能自动证明正式页面生命周期、稳定消息身份及生产数据库组合 |
| 库/管线升级后恢复 | 区分锚点格式与渲染配置身份；新布局不能直接解释旧偏移。重验成功则定位，否则明确无法精确定位，仍保留父消息、引用与原文；不跳到相似文字 | 兼容样本须在锁定正式版和实际升级时补，不要求当前重跑原型；不存在“所有升级都无损”的承诺 |

依据：需求 §5.2–5.3、§8.4 第 214 行；架构 §14、§14.R 第 250–262 行。纸面反例“渲染成功就允许表格分支”和“新控件沿用旧偏移”均被现有规则拒绝。待用户确认的是推荐支持面是否足够；待实施证明的是每个承诺结构的显示、引用和恢复。固定 LiveMarkdown 2.5.1 / Avalonia 12.1.4 仍只是已有小样的版本证据，不在本轮转成正式锁版或完整支持结论。

## 流程二：Root→Menu→两级详情→GoBack→跨工作区/重启（MW-07）

**具体动作：** 启动并恢复工作区 W1；从探索主区进入火车会话 A，创建蒸汽机分支 B，再创建内燃机分支 C。执行普通 GoBack，再从已有入口进入 C 并使用“返回来源”；随后切到 W2，再回 W1，最后正常退出并启动新进程。以下历史表示只用于说明当前页面与返回层次，不强制实施者使用某个容器类型。

| 步骤 | v3 的纸面期望 | 最低证明与当前缺证 |
| --- | --- | --- |
| Root→工作台 | Root 服务负责根/窗口启动生命周期，初始化/恢复结束后进入主工作台 | 应实际演示根生命周期；单窗口初始化是否满足课程窗口语义仍需说明，存疑时问老师。当前无正式 Root 实现或课程批准 |
| Menu→探索 | Menu 服务切主区，目标和参数走统一契约；ViewModel 经 ViewLocator 选择 View 并成为实际可见内容 | 需要结构检查及实际可见 View/DataContext；注册了 ViewLocator 类名不能代替它参与渲染 |
| A→B→C 两级详情 | Content 服务发出推栈操作；主 VM 是唯一业务内容栈权威。概念上当前历史 A→B→C，生成任务不依赖这些 View 实例 | 需要实际两次详情进入及栈状态观察；服务、View 不得另有可弹出的业务栈。当前没有正式页面/栈运行证据 |
| C 的普通 GoBack | 回到上一访问页 B，按访问历史；与“返回来源”定位父消息选区是不同意图 | 应用实际位置区分两者，不能以两个按钮同调一种导航掩盖语义。当前原型依据不能替代正式三层导航证明 |
| 重新打开 C→返回来源 | 恢复 C 自己阅读位置后，来源命令按 C 的分支关系到 B 的选区；普通历史与来源关系互不冒充 | 栈如何去重/定位属于实施细节，但不得创建新分支，或因恢复旧页面销毁来源事实；需正式链路验证 |
| 切 W2→回 W1 | 按 §11.R 推荐，旧边界历史不再可跨界弹出；目标最近页重建为当前边界入口。W1 阅读位置/草稿和后台任务仍有各自状态 | 跨边界清历史是待用户决定的体验限制，当前不能称已批准。通过条件是 GoBack 不弹到 W2/旧 Menu 的陈旧页，内容/草稿仍在 |
| 新进程恢复 W1 | 按待决推荐恢复最后有效页及阅读位置，不恢复完整后退栈；未结束请求标中断且不自动重发 | 须新进程验证正式数据库、页面、草稿、来源和任务状态；旧原型真实重启记录不是本项正式验收 |

依据：架构 §11.R 第 205–207 行、§12、§18、§19；需求 §5.3。纸面没有发现第二套业务栈或返回来源与 GoBack 混用的授权。保留当前边界历史的丢失成本待用户选择；这不是删除三层导航职责。课程要求仍应由真实 Root/Menu/两级 Content/后退和 ViewLocator 路径证明。

## 流程三：正式首版演示、源码资源包与 PDF（MW-10、MW-11）

**具体交付流程：** 在明确的演示平台和正式依赖下，用户填写一套实际接口，完成提问→两层分支→返回→总结→候选处理/编辑→网络再进入→退出/新进程恢复；随后断开 AI 服务，仍阅读已保存内容。最后准备课程源码资源压缩包与报告 PDF。

| 交付点 | 纸面应达到的条件 | 当前状态与不能替代的证据 |
| --- | --- | --- |
| 完整首版演示 | 同一正式实现贯通探索和回顾两个阶段，真实 AI、LiveMarkdown 来源适配、SQLite、总结和网络相互配合；取消/失败清晰且不伪造成功 | 尚无正式产品。固定模拟回答可作演示替身，但不能据此声称真实服务、上下文传递与总结通过；一个实际服务的验证不能推成所有兼容端点 |
| macOS/Windows | 在正式支持/演示平台核对中文输入、选区、窄窗/缩放和来源恢复，平台证据分别记录 | 现有为当前 macOS arm64 原型记录，Windows 未验；不能用 Avalonia 包跨平台或 macOS 运行推出 Windows 已通过 |
| 长文/并发 | 先明确目标规模、参考设备与可接受响应，再验证两请求下阅读/选区/输入及保存节奏 | 当前没有正式长文性能基准；8/8、31/31 和约 16 秒固定输出都不是性能阈值或吞吐证明 |
| 课程工作量 | 固定 DailyPoetryA 参照版本与页面、类/接口计数口径，按同口径核对有意义职责 | 只有候选目录和职责映射，没有老师认可数值基准；不能用会话数量、原型测试数、四工程数量证明达标 |
| 三层/注入/单向依赖 | 通过上述真实导航路径及静态依赖、统一参数/服务契约审查证明课程思想和具体导航职责 | 不强迫四工程改两工程；也不因删繁删掉真正 Root/Menu/Content、主 VM 栈或 ViewLocator |
| 源码资源压缩包 | 实际包 ≤10MB，只含源码资源，不含编译结果；检查实际条目和大小 | 尚无正式包，本轮未生成。应用自包含安装包体积不是这条的考核对象；原型 artifacts/bin/obj 不应直接混入源码提交物 |
| 报告 PDF | 按原件模板覆盖背景、需求、设计、实现、测试、总结展望，截图与环境对应真实被验证版本 | 尚无正式报告或 PDF；有 Markdown 设计说明不能代替实际 PDF 提交，也不能把纸面场景写成已执行测试 |
| 价值验证 | 隔两三天回顾、寻找具体解释与来源，记录使用比较与负担 | 产品功能完成、用户原型确认和课程结构达标仍不能替代延迟回顾结果 |

删繁检查：v3 只将手动拖动节点列为可讨论推迟项，仍保留稳定自动布局、来源追溯、查找、视口恢复和首版阶段二，也未取消任何课程导航职责。因此未发现“为了轻量化把完整首版/课程职责删掉”的新问题。拖动属于已确认范围，其实际删减依旧需要用户决定，不因本轮纸面分析自动生效。

依据：需求 §8–10；架构 §13、§17–19，特别是第 334–345 行。课程原件依据沿用 [首轮取证](../round-1/verification-evidence-course.json)，本轮未重新解释或杜撰数量门槛。
