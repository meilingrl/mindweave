# 证据层级与只读核对边界

## 五种结论分别保留

| 层级 | 原始依据 | 本轮能作出的判断 | 本轮未作的验证 |
| --- | --- | --- | --- |
| 原型技术验证 | 两原型 README 历史构建/测试/实机记录；必要处静态源码 | 原记录有具体场景，局部实现与声明相符 | 没有重跑 31/31、8/8 或重新构建、启动程序 |
| 用户操作验收 | Avalonia 聊天原型 README 的明确确认记录 | 原文记录当前 macOS 原型获用户确认 | 不替用户重作验收；LiveMarkdown 记录不能自动继承该用户确认 |
| 正式产品实现 | 根 README、需求/架构状态、当前源码仅两独立原型 | 文档未宣称已实现正式产品 | 没有创建正式工程或把原型整合 |
| 课程验收 | 架构 §4 指向的课程原件；见 round-1 验证审查 | 逐项映射可提出设计/证据缺口 | 不将技术选型、四工程或测试数量称为课程通过 |
| 产品价值验证 | 需求 §10 的比较与延迟回顾提议 | 验证方法有方向，实际效用尚无本轮数据 | 未招募用户、比较竞品或执行隔日回顾 |

## 基线与链接语境

v1 两文件保持原字节，因此其中相对原型/课程链接仍按原文件目录理解。原文件路径和 SHA-256 见 baseline-manifest.json。副本 v2 起修复指向原型/课程的相对路径，仅改变副本链接，不更新原 README。

## 本轮明确不做

不运行原型、不编译、不测试、不执行训练或高负载实验；不读写两个原型的 Library/Application Support 用户状态。外库只读查询固定版本官方资料，失败与成功读取方式在 official-library-check.md 中记录。
