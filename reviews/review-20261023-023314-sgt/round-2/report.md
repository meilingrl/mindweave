# 第二轮汇总与裁决：v2 → v3

[产品复核](product.md) · [架构复核](architecture.md) · [验证复核](verification.md)

三者分别复核 v2 与首轮裁决，未读取其他人的当轮意见。主 Agent 逐份阅读并核对原有提案。本轮没有运行任何原型、构建或测试。

## 有效修订与剩余问题

MW-01/03/05/08 的首轮反例在推荐方案内可解释；MW-06 的分类和无损打开底线、MW-07 唯一栈、MW-09 的支持与降级、MW-10 课程映射均文本有效。未因此宣称用户批准、课程达标或实现安全。

| 问题 | 裁决与 v3 变化 |
| --- | --- |
| MW-02 候选／历史手改绕过采用 | 采纳：推荐仅当前采用版本可编辑，候选先采用再编辑，采用／丢弃释放候选位置；编辑基线变化不无声覆盖；手改继承来源范围、不把后来消息标已总结。这是新的体验限制，仍待用户确认 |
| MW-04/06 退出失败后只留窗口却无法继续 | 采纳：推荐明确重试退出／返回工作区，返回只重新接收新操作，不复活旧任务／队列；重试保存最新状态。整体恢复原本待决，仍未批准 |
| MW-12（架构 A2-01）自动标题迟到覆盖手改 | 新增稳定编号并采纳最小保护：仅未手改且基线匹配才应用结果，否则丢弃过时标题；无新标题管理功能 |

## 不采纳的扩大

不加入候选直接编辑、自动合并、标题历史、标题弹窗、多实例协作或数据库修复工具。没有用更多状态UI解决每个边界。单候选先处理的额外操作、跨工作区/Menu 清栈会失去旧详情历史等真实成本交给用户决定。

## 形成版本与下一轮

[v3 需求](../v3/initial-requirements.md)与[v3 架构](../v3/architecture-discussion.md)为完整副本，v2 已冻结。第三轮以反例和完整真实流程做纸面推演：多层分支＋后台任务、总结＋手改、退出失败＋重启、多根回顾、课程演示与最小范围。纸面推演不是实机或数据库测试。

第二轮仍有一个新增高价值问题及两处旧项剩余反例，因此不计为“无新高价值问题”的收敛轮。
